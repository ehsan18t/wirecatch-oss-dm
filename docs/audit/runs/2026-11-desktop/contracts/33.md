# Contract 33: repo-checks

## Gate (`scripts/gate.mjs`)

- `node scripts/gate.mjs [names] [--no-desktop] [--no-fail-fast] [--skip=CHECK]`. No names runs `DEFAULT`: `repo`, `rust`, `release`, `js`, `browser`, `supply-chain`. Exit 1 on a `GateError`; anything else is rethrown.
- Commands that are not checks: `--list`, `--install-tools`, `--tool-specs`, `commit-msg FILE`.
- Starts on Node's own modules alone (test in `imports.test.mjs`): the Rust and supply-chain CI jobs run without `pnpm install`. Checks that need packages load them when they run.
- Groups: `rust-lint` (fmt, lint-policy, cfg-allow, test-timing, clippy, clippy-linux, clippy-http3, engine-docs, docs), `rust-test` (test, test-http3), `release` (engine-package, msrv), `js` (js-policy, protocol, js-check, js-lint, js-test, js-build), `repo` (text, exceptions, product, commits), `supply-chain` (unused-deps, deny, notices, npm-audit), `browser` (e2e-extension), `publish`, `publish-extension`, `release-build`, `release-build-extension`.
- CI runs the groups in separate jobs on Windows and Ubuntu; together they equal `DEFAULT`. `clippy-linux` runs only away from Linux.

## What the checks rely on

- `cfg-allow`, `test-timing`, `exceptions` and `text` use `git grep --untracked`, so they need a git checkout and read untracked, not ignored files too.
- `commits` reads `GATE_COMMIT_RANGE`, otherwise `origin/main..HEAD`. `protocol` reads `origin/main` for released snapshots.
- The `test` check sets `WIRECATCH_TEST_BRIDGE` to `<target>/debug/<bridge>`, built with `wirecatch-bridge/test-overrides`, read by `crates/test-support/src/bridge.rs`.
- `exceptions`: every lint attribute or disable comment matches one `LINT_EXCEPTIONS` entry by file and exact lint set, and every entry is used. Macro-supplied lints (`$lint`) are not seen.
- `test-timing` reads Rust test code only: all of a file under `tests/` or named `tests.rs`, and inline `#[cfg(test)] mod x { .. }`. A test module in a file of another name (`crates/engine/src/segment.rs` declares `proptests`) and helper crates such as `test-support` are not read. Tests with `start_paused = true` are exempt. It misses `recv_timeout` (33-2).
- `product.test.mjs` fails if any untracked file holds a placeholder value, so docs must not write the mark followed by a capital letter.

## Product identity

- `config/product.toml` is the only home. `readProduct` checks every value by `SCHEMA`: unknown or missing keys, unquotable characters (`"`, `$`, backtick, backslash), channel clashes ignoring case, and the Chromium id against its key are errors.
- Generated by `pnpm product:generate` (`outputs()`): `crates/product/src/lib.rs`, `packages/product/src/index.ts`, `SECURITY.md`, identity fields of the root `Cargo.toml`, the `[[bin]]` name in the bridge, CLI and desktop manifests, and every `package.json`. `generate` then brings `Cargo.lock`'s workspace crates to the product version with `cargo update --workspace --offline`.
- The `product` check fails when a generated file or `Cargo.lock` is stale or missing, or a crate does not inherit version, license, authors, repository and homepage.
- `publish` fails while a placeholder remains, in product.toml, generated files or anywhere else (tests and product.toml aside). `release-build` only warns. `config/templates/prerm.sh` is filled by `scripts/package.mjs` at packaging time and is outside the `product` check.
- `RELEASES_API_URL` requires `links.repository` to be a GitHub repository.

## Workspace configuration

- Every crate must have `[lints] workspace = true`. Lints are `warn`; the gate adds `-D warnings`.
- Rust is the newest stable (`rust-toolchain.toml`, D56); the engine alone has an older promise (`rust-version`, 1.88), checked with default features.
- Release profile: thin LTO, one codegen unit, stripped, `panic = "abort"`. `cargo ui` uses `[profile.ui]`, output in `target/ui`.
- `deny.toml` covers Windows and Linux on x86_64 and aarch64, all features, crates.io only, no git sources.
- `.cargo/config.toml` points `TS_RS_EXPORT_DIR` at `target/ts-rs` unless the environment sets it.
- Files are LF everywhere (`.gitattributes`), which the generators' text comparison depends on.
