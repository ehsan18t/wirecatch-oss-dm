# Contract 09: request-routing

## `net_guard`

- `PrivateNetwork` (`Auto`, `Block`, `Allow`) and `AddressKind` are public. `AddressKind::of` unwraps IPv4-mapped, IPv4-compatible, NAT64 `64:ff9b::/96` and 6to4 addresses; Teredo, `::ffff:0:a.b.c.d` and `64:ff9b:1::/48` are not unwrapped. Everything but `Public` counts as local.
- `private_guard(url, rule, timeout, proxies)` returns `None` for `Allow`, and for `Auto` when the host's addresses are known and all local (one separate lookup). Otherwise it returns a `Guard` and a `FilteringResolver`. It waits up to `timeout` and takes no cancel token.
- `Guard` must be called by whoever sends the request. `http::send` does so for each hop. The check allows the starting origin only when its host is written as an address. A name is refused when it has addresses and all are local. A name that does not resolve or times out is allowed. Each name's answer is kept for the guard's life, including a timeout's "allowed".
- `FilteringResolver` drops local addresses and fails when none is left, except for the names in `Proxies::host_names`, which it returns unfiltered. Its failure reaches callers as a connect error (`Error::Network`), not `Error::PrivateNetwork`.
- **Guards cover HTTP and HTTPS only.** `download_with` makes none for an FTP link, whatever `private_network` says, and FTP name lookups are not filtered.
- HTTP/3 is switched off for a download with a guard. Callers must build clients with the resolver (`Clients::set_resolver`, or `.dns_resolver` on `Clients::builder`).
- With an HTTP or `socks5h` proxy the guard checks names on this computer before each request, but the proxy resolves them, so a name that is local only for the proxy is not caught. `socks4://` and `socks5://` resolve here through the filter.
- Under `Block`, a starting URL written as a local address is allowed: the caller must refuse it (core does, through `wirecatch_sites::refuses_address`).

## `proxy`

- `ProxyChoice`: `System` (default: environment, then on Windows the system's manual proxy, read when the clients are made), `Direct`, `Manual(ManualProxies)`. `ProxyChoice::route` and `ManualProxies::from_system` read the settings at each call.
- `Proxies` is the one source for the HTTP client (`Proxies::client`, which also stops reqwest reading settings of its own), HTTP/3, FTP (`ftp_route`) and retries (`goes_through`).
- A scheme's own proxy comes before `all`. An unreadable proxy still counts for the engine's decisions (FTP refused, HTTP/3 off), while the HTTP client goes directly around it. For `Manual`, `DownloadOptions::validate` refuses an unreadable value with `InvalidOption("proxy")`, so this applies only to `System`.
- In a CGI program (`REQUEST_METHOD` set), no proxy and no exceptions are read.
- Any proxy variable replaces the whole system setting. `NO_PROXY` replaces the system's exceptions.
- Exceptions: `*.x` covers `x` and its subdomains, `10.*` becomes a network, `*` covers every name but no address, `<local>` covers names without a dot. Other patterns match nothing, and that includes IPv6 addresses in brackets.
- `ftp_route(host)`: `Ok(None)` is direct, `Ok(Some(socks))` is SOCKS5 only, `Err(setting)` is refused, naming where the proxy is set. SOCKS4 and HTTP proxies cannot carry FTP; `ftp_direct` turns the refusal into going directly.
- A Windows `socks=` entry is treated as SOCKS4 and handed to the client as `socks4://`.
- `Debug` for `Proxy`, `Proxies` and `ManualProxies`, and `ProxyRoute::Through`, show `***` in place of a login. `ProxySetting`'s text and `remedy` hold no proxy value.

## `url`

- `WEB_SCHEMES`, `FTP_SCHEMES`, `is_supported`, `is_ftp`: public. `http`, `https`, `ftp`, `ftps` and `ftpes` are the only links the engine downloads.
- `without_credentials` removes user name and password; `without_password` (crate-private) keeps the user name. A URL that cannot carry credentials comes back unchanged. Neither fails.
- `ftps` and `ftpes` are not special schemes to the URL parser: a host written as an IPv4 address is still `Host::Domain` (`ftps://127.0.0.1/`), and their origin is opaque.
