# Contract 27: settings-and-queue-forms

## What this chunk offers others (all `pub(super)` or `pub` within `crates/desktop`)

- `settings::{about_screen, shortcuts_screen, Page, PAGES, OpenOn}`, `MainWindow::settings`. The palette and notices open a page through `OpenOn`; a new `opening` value restarts the screen on `page`.
- `queue_dialog::open(library, Option<QueueId>, main, ..)`, `queue_delete::ask`, `MainWindow::{edit_queue, delete_queue, queue_header, nudge}`, `queue_header::{rules_on, set_rules}`.
- `proxy_dialog::{open, ask_delete, address, shown_name, kind_label, Users, Created}`, `queue_proxy::BYPASS_HELP`.
- `backup_dialog::{open, Direction}`, `link_trial::{LinkTrial, Draft, Drafted}`.
- `settings::general::app_update_field` is shared with About.

## How the forms behave

- Every settings control reads from `Library` and changes through `api::change_settings` with a patch naming one field; nothing changes on screen until `SettingsChanged` returns. A refusal is a notification in `backend::window_in_front`, which falls back to any window when none is active.
- Sending a whole group: `change_proxy` sends all of `ProxySettings`, and `files::change_rule` sends all of `categories`, each built from the library's current copy.
- List fields (`list_field`) save 800 ms after typing stops and on every blur, changed or not. While unfocused they follow the saved value; while focused they do not.
- Number fields (gpui-kit `SettingField::number_input`) save on each keystroke that parses, clamped; the field clamps its text on blur.
- The queue editor (`QueueForm`) and the proxy editor hold a copy until Save, then send whole settings through `api::{create,update}_queue` or `api::{create,update}_proxy_server`. Failures stay in the form. A new queue's view opens on success.
- A queue's `Setting::Own` limits are read from text on every save, so the speed limit is rounded to what the field shows (finding 27-5). Fields switched off send `Setting::Global`, and the typed value is dropped.
- `RulesForm::add_downloads`: `Auto` when switched on or holding any rule, else `Manual`. An unchecked kind of rule saves empty.
- Test a link: `api::try_link` with `DraftRules` of the editor, or with no draft in Settings. The core decides; the form only words the answer. An answer is dropped on any edit of the link or the rules, not on a rename.
- Deleting a queue: removal of the chosen downloads, awaited, then `api::delete_queue`. Files of finished downloads go only when both boxes are ticked; partial files always go with a removed download.
- Deleting a proxy: the replacement is applied by the core to the global setting and to queues that name it.
- Passwords reach a form only as `has_password`. `ProxyServerDraft.password`: empty field is `Keep` (which the core turns into forgetting when type, host, port or user changed, finding 27-1), typed text is `Set(Some)`, Remove saved is `Set(None)`.
- Import is two steps on the same path: `preview_import`, then `import_settings`, which reads the file again. The preview does not cover proxies (finding 27-2). The Done step shows only the path.

## Dialogs and keys

- All dialogs open through `crate::ui::dialog::{open, open_alert}`. Enter reaches the dialog's `Confirm`: the queue and proxy editors bind it to Save without closing; dialogs with no `on_ok` close on it without acting (finding 27-3). `LinkTrial` swallows `Confirm` so Enter only tries the link.
- A proxy editor opened from a queue's form stacks over it; `Created` hands the new id back to the queue's `ProxyForm`.

## What it relies on

- `Library` fields `settings`, `queues`, `proxies`, `addons`, `downloads`. `settings` is `None` until loaded, and `current` then gives each control its fallback.
- `Library` notifies on every progress tick, so an `observe` on it runs up to ten times a second (finding 27-8).
- The core validates everything: these forms check only what they word better themselves (a queue's name, whole numbers, a limit above zero, a schedule's days and times).
