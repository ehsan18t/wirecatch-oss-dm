# Contract 02: engine-http

How `http`, `http3`, `transport`, `retry`, `error` and `Fetcher` really behave, for the chunks above them.

## Errors (`wirecatch_engine::Error`)

- `#[non_exhaustive]`. `is_retryable` is true only for `Network`, `PrematureEof`, `Stalled`, `HttpStatus` 408, 425, 429, 500, 502, 503, 504, and FTP 4xx. Everything else ends the attempt at once.
- `Error::source()` is `None` for `Network`: the cause is inside `NetworkError`, whose `Display` already includes the deepest cause. `NetworkError` offers `is_timeout` and `is_connect`; `is_timeout` is always false for a QUIC library error.
- `Certificate` is split from `Network` and never retried. `ProxyLoginRefused` comes from a `407`, or from matching the text of `hyper-util` errors (tests catch a rewording).
- `HttpStatus.url` and reqwest's error text carry the full URL, query included; the log's redaction hides it, a person's message does not use it.

## Which answer is trusted

- `check_partial` (every `206`, on every protocol and in `Fetcher`): start must equal the offset asked for, else `RangeNotHonored`; a known size that differs, or validators that contradict, give `RemoteChanged`. It does not compare the span's end with what was asked, nor `Content-Length` with the span: the caller stops at its own end.
- `check_whole` (a `200` that continues a transfer): same size when both known, validators do not contradict.
- `Validators::contradicts` refuses only a contradiction: both have an `ETag` and they differ weakly (`W/"x"` equals `"x"`), else both have a strong `Last-Modified` (a second older than `Date`) and they differ. A validator only one side carries proves nothing. Two versions without validators and of one size are joined undetected.
- `fetch` with `ranged` turns a `200` into `RangeNotHonored`. A `416` becomes `HttpStatus` whatever its `Content-Range` says.
- First answer (`probe`): `206` with a size means ranged; `206` with no size means not ranged and unknown size, the body's end is the file's end; `200` means not ranged, size from `Content-Length`; `416` with `bytes */0` means an empty file, and the body handed over is then not the file (the caller must not write it). Any other status fails. A `206` with an unreadable `Content-Range` fails with no retry.
- A non-ASCII byte anywhere in `Content-Disposition` gives `file_name: None` (finding 02-2).

## Requests

- `Session::new` moves `user:password@` into `Authorization` and returns a URL without it. `RequestHeaders::for_url` gives all caller headers only to the exact origin (scheme, host, port) of that URL; others get `Accept`, `Accept-Language`, `Cache-Control`, `DNT`, `Pragma`, `User-Agent` and an origin-only `Referer`.
- The engine does not remove or replace a caller's `Range` or `Accept-Encoding` over TCP: `Range` is appended and a caller's `Accept-Encoding` wins over `identity`. HTTP/3 overrides both. Callers must filter first, as `crates/core/src/headers.rs` does.
- `http::send` follows 301, 302, 303, 307, 308 itself, up to `MAX_REDIRECTS` (20) hops, checks the guard before each hop, refuses `https` to `http` unless allowed, keeps no cookies, and is bounded by `stall_timeout` per hop for the headers. The guard's own wait is not raced against the cancel token.
- After the first request every request of a run goes to `final_url`, never back to the original link (finding 02-1). `Retry-After` is read only on 429 and 503, capped at 300 s.

## Retry policy (`retry::Attempts`)

- One policy for the first request, workers and `Fetcher`. `max_retries` counts attempts in a row that received nothing (default 6, so 7 tries); progress resets it. The budget is checked before step-back, so a very low `max_retries` gives up where stepping back could have helped; the default steps back first.
- A connection the system reports refused on a link through a proxy gives up at once (D102).
- `Refusals::StepBack` (workers only): busy statuses, non-timeout network errors, `PrematureEof`, FTP 421, 425, 530 count as refusals and are retried even if not retryable; the second in a row, any `Retry-After` whatever its length, or a pause at the cap returns `StepBackOrRetry`. `Refusals::AsFailures` (first request, `Fetcher`) treats them like any failure.
- Pauses: `first` doubling to `max`, plus jitter below `min(250 ms, first / 2)`; `Retry-After` replaces the pause, jitter is only added.

## Clients and TLS

- `Clients::new` reads the system's certificate store once per process, blocking: async callers check `shared_ready` first. All clients share one TLS session cache. One `reqwest::Client` per worker gives one TCP connection per worker. Redirects off, `Accept-Encoding: identity` by default, proxy decided only by `Proxies`.
- HTTP/3: only after the first answer's `Alt-Svc` for the same host, only over `https`, only when no proxy applies, to the IP the first request reached. Any QUIC or unexpected-status failure marks HTTP/3 broken for the whole download and falls back to TCP without using a retry; busy and changed-file answers are handled as over TCP. `session.guard` is not consulted for QUIC: the address is pinned instead.

## Fetcher

- Clones share everything. `new` uses `PrivateNetwork::Auto`, for a URL the person chose only. A link's own `user:password@` is dropped except on the URL it was created with.
- `get` refuses above `limit` before reading when the size is known, and while reading when not; `TooLarge` is not retried. A server ignoring ranges is handled by skipping and stopping at the end.
- `save` creates or truncates first, even for an empty range. It flushes on return, also after an error or a cancel by token, but never syncs to the disk, and a dropped future loses up to 256 KiB already reported through `on_bytes` (finding 02-6). `on_bytes` never counts a byte twice.
- Each transfer stays on one client for all its retries. Skipped bytes are not paced (finding 02-3). A resource with no size whose continuation is shorter than what was already received ends without error unless validators say otherwise.
