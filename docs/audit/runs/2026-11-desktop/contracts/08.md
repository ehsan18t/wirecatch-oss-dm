# Contract 08: local-endpoint (`wirecatch-ipc`)

## Public API

- `Listener::bind_keyed(channel, &Folders)`: the app's way to listen. Takes `endpoint-key.lock` in `folders.key` first and keeps it for the listener's life. `Listener::bind(&Endpoint)`: no key or key lock, for tests and tools.
- `Listener::accept()`: cancel-safe. An error concerns one attempt, so keep calling it. `PeerRefused` means no pause is needed; other errors may repeat (the shell pauses).
- `endpoint()`, `endpoint_for(channel)`, `endpoint_in(channel, &Folders)`: for clients. They only read the key, so call them again at every attempt to connect. On Linux they also create the socket's folder when it is missing.
- `connect(&Endpoint)`: checks the owner before returning, and writes nothing.
- `Connection`: `AsyncRead + AsyncWrite + Send + Unpin`. Frames come from `wirecatch_protocol::frame`; this crate does not frame.
- `Endpoint`: `Display` and `Debug` hide the key. `as_os_str()` holds the real name, so never log it. `from_raw` carries no key to hide.
- `Folders { key, runtime }`, `Folders::of_user`, `key_folder`.
- `elevation()` gives `Standard`, `Elevated` or `AlwaysAdministrator`. On Windows also `ProcessAccount`, `Sid` and `wide`.

## Errors as they really occur

| Error             | When                                                                                                                                                                            |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `NotRunning`      | Windows: `ERROR_FILE_NOT_FOUND`. Linux: `NotFound` or `ConnectionRefused`.                                                                                                      |
| `WrongOwner`      | Only when the pipe or socket opened and its owner differs. A pipe that shuts the user out gives `Io` with access denied (08-3).                                                 |
| `AlreadyInUse`    | The key lock is held, or a plain name check found our own owner or a busy pipe. Under `bind_keyed` a busy pipe or one owned by the user may not be Wirecatch (08-1, 08-2).      |
| `EndpointTaken`   | Windows listener only: another owner, or access denied while probing. Triggers one key renewal in `bind_keyed`.                                                                 |
| `UnsafeDirectory` | Linux, listener and client: the folder is a link, not a folder, not owned by the user, or has group or other access. Triggers one key renewal for the listener, only in `/tmp`. |
| `NoEndpointKey`   | Client only: no key file. Treat as not running.                                                                                                                                 |
| `BadEndpointKey`  | Damaged key (client only; the listener replaces it), or a key that is not private. Refused by both. A Linux link gives `Io` instead (08-4).                                     |
| `PeerRefused`     | One client refused. The listener stays usable.                                                                                                                                  |

## Guarantees

- One listener per channel and account while the key lock is held. The system releases the lock when the process ends, however it ends.
- Only the holder of the lock writes the key, written aside and renamed, so a reader sees the old or the new key, never a part. The key changes only when missing, damaged, or when `bind_keyed` sees `EndpointTaken` or `UnsafeDirectory`. Renewal happens at most once per bind.
- Windows pipe: owner the user, protected DACL with only the user, label at the listener's integrity with no-write-up and no-read-up, first instance flag, remote clients rejected.
- Windows listener serves only the same user at its integrity or above, outside a restricted or `AppContainer` token, opened at the identification level. Plain `CreateFile` and anonymous clients are refused.
- Windows connector opens at the identification level, so a server cannot act as the client. It checks the owner SID only: not the server's integrity (08-1).
- Linux socket: mode 0600 in a 0700 folder, with `SO_PEERCRED` checked on both ends. A stale socket is removed only under the socket's own lock and only on `ConnectionRefused`. The `/tmp` folder outlives the listener.
- Windows key file: owner the user, access for the user alone, no label, so a low-integrity program of the user can read it (08-1). Administrators or the system as owner is accepted when reading (D41.4). Linux: mode 0600 and the exact uid.
- `Sid` values compare whole; `Listener` drops its socket before its locks.

## What it does not do

- It is no boundary against a program of the same user at the same level (D41.2).
- It does not look at what a connection carries, set a size limit or time anything out, apart from the 2 second wait in the Windows `connect` while every pipe instance is busy.
