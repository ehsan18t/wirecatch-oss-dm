# Contract 31: test-servers (`wirecatch-test-support`)

Unpublished. Used only by tests, examples and benches. Features: `servers` (HTTP, files, FTP, silent, proxy, TLS), `http3`, `resume`, `logs`, `bridge`, `downloads`, `redaction`. Without features it builds no HTTP or TLS stack. Every server binds a free port on 127.0.0.1 and stops with the test's runtime.

## Always available

- `PATIENCE` (120 s) bounds a hang; `QUIET` (300 ms) is a window in which something must not happen.
- `test_data` and `seeded_data` give deterministic bytes, built in O(n); `ts_segment` starts with the sync byte.
- `private_dir` makes a unique folder, mode 0700 on Unix, removed on drop. `remove()` reports a held file, so a test can catch a handle left open on Windows.
- `real_ffmpeg` returns `None` with a note, or panics when `WIRECATCH_REQUIRE_FFMPEG=1`.

## `http::TestServer`

- One buffer at every path except `/`: the route is `/{*path}`, so `/` gets the router's own `404`, not logged and not counted by `arrived`.
- Default answer is `200` with the whole body; `Range` is honoured only with `ranges`.
- The order of decisions in a request: `hold` wait, `refuse_paths`, `max_range`, `redirect`, `hang`, `busy`, `answer_delay`, then the file, with `416` for a start at or past the end and `max_connections` last.
- The config is copied when the request arrives, so `configure` during a `hold` does not change held requests.
- Sequence numbers (`hang`, `busy`, `drop_first`, `short_first`) count every request on every path, from 0.
- `Seen::at` and `wall` are the arrival time. The log entry is pushed when the answer is decided, so `stats.seen()` is in answer order and leaves out held requests; `arrived` and `wait_for_request` include them.
- A `hang` request is logged with status `408` although nothing is ever sent.
- `Seen::sent` counts bytes handed to hyper, not bytes the client received. A held body (`hold_bodies_from`) counts 0.
- `drop_first` cuts only at a chunk boundary (64 KiB unthrottled) and does nothing to an answer of at most one chunk (31-3).
- `max_concurrent` counts bodies being served until the body is dropped.
- Ranges with an end below the start are not handled: the handler panics on the length, which drops that connection. Suffix ranges (`bytes=-n`) get `200`.

## `files::FileServer`

- Files by exact encoded path; anything else is `404`. Ranges are always on.
- `fail` uses up one failure per request under one lock. `delay` also applies to failures.
- `Seen` is built after the delay (31-4); `Seen::sent` is always 0; hung requests are never logged.
- `max_active` counts a request only until its response is built, not while its body goes out, so it sees overlap only during `delay` or `hang`. A `throttle` alone does not raise it.

## `ftp::FtpServer`

- Commands other than `AUTH`, `USER`, `PASS`, `QUIT`, `NOOP` and `OPTS` need a login. Only passive mode. `TYPE` is always accepted and data is always binary.
- A config is copied per session; `configure` affects later sessions only.
- With TLS, each session has its own ticket key, so a data connection can resume only its own control session. A full handshake is still served: tests assert on `data_handshakes`.
- `AUTH TLS` discards what was buffered before TLS starts.
- `drop_first` cuts exactly, counted from the transfer's offset. `hold_probe` holds only that transfer number, and only from byte 0.
- `SIZE` and `MDTM` ignore `Quirk::Utf8AfterOpts`; only `RETR` applies it.
- `held_replies` only ever goes up, despite its doc saying "currently": read it as a total and compare with an earlier value, as `crates/engine/tests/ftp.rs` does.
- `DATA_CONNECT_TIMEOUT` (10 s) does not race the engine, which connects before sending `RETR`.

## `http3`

- `start_tcp` (HTTP/2 or HTTP/1.1) and `start_h3` / `start_h3_breaking` serve one buffer. A range that cannot be met gets `200` with the whole body, never `416` (31-1), and no `Accept-Ranges` is sent.
- `Counts::bytes`: on TCP the whole body is counted when the answer is built; on HTTP/3 only what `send_data` took, and nothing on a breaking stream. `largest_ask` is `u64::MAX` for an open range or none.
- `start_h3_breaking` truly resets the send side (`stop_stream` in h3 0.0.8), on every stream.
- `Blackhole::attempts` counts distinct source addresses. That equals attempts because the engine opens a new `quinn::Endpoint` per connection; a shared endpoint would make it undercount.

## Others

- `proxy::SocksServer`: treats any SOCKS command as `CONNECT`. `LoginWall`: `407` to everything.
- `silent::SilentServer`: holds every socket. `url` does not normalise a leading `/`.
- `resume::kept_ranges` relies on `remaining` being sorted and half-open, which `SegmentTable::remaining` guarantees. `asked_again` treats a request with no parsable range as the whole file.
- `logs::Logs::capture` sees only the calling thread. On a multi-threaded runtime or in `spawn_blocking` it misses events, so a check that something was not logged would pass without proof. A process-wide capture uses `subscriber()` in a test binary of its own. Span and event field values are `Debug` text except strings, which are stored plain.
- `bridge::bridge_exe` uses `WIRECATCH_TEST_BRIDGE` if set, otherwise runs `cargo build` once per process into this test's target folder, in dev or release only.
- `TestCertificate`: self-signed for `127.0.0.1` and `localhost`, TLS 1.2 and 1.3, ring provider.
