# Contract 07: browser-handover

## `wirecatch_server::serve_connection(manager, stream)`

- The first frame must be `hello`; anything else gets one error answer and the connection closes with `Ok`. Versions are agreed once (D32); every message passes `send`, which leaves out what the agreed version lacks.
- Requests run as detached tasks, at most `MAX_REQUESTS_IN_FLIGHT` (64) per connection; one over gets `LimitReached` at once. Answers come in any order, matched by id. A request whose client left still finishes.
- Oversized frames are skipped unstored and answered with `UNKNOWN_REQUEST_ID`; the connection survives bad frames.
- A lagged event subscriber gets the three settings and queue snapshots; lost notices are not resent.
- A connection holds a strong `Manager`, so it does not end when the manager shuts down: its owner must stop the task (07-6).
- The server never checks which `ClientKind` makes a call.

## `Manager::add_capture` and `withdraw_capture`

- Order: handover id check, link check, read of state (cookies from the jar if any, queue, who chose the link), known handover, local network refusal (`NotStarted`), join an unfinished download, media path, question, or insert.
- Known handover: the same answer, after waiting up to `capture_timeout + stop_timeout` if the first add is undecided; `NotStarted` if the first failed. Two copies racing make one download.
- Started: answered only after the settler cancels `answered` or the run has ended and `server_answered()` is true, within `capture_timeout` of arrival. Otherwise `NotStarted`, and the row is hidden at once and removed in the background.
- Exception: a capture joining an unfinished download gets `capture_action` of that row at once, `Started` for a `Connecting` row (07-2). A joining handover is `Target::Confirmed`: withdrawing it answers `AlreadyStarted`.
- `Queued` and `AwaitingConfirmation` mean the link has not been tried. `capture_action` answers `Queued` for anything not running or finished.
- `withdraw_capture` outcomes: `Withdrawn` for an undecided, queued or question handover; `AlreadyStarted` once the server answered or the person confirmed (also while confirming); `NotFound` for unknown, dismissed, or a row gone.
- Handovers live in memory only (D27.9) and at most 1000 are remembered, except those undecided or on a question.

## Questions

- `confirm_capture` takes the question off first; on failure it puts it back and the handovers return to `Pending`. `reject_capture` dismisses. A failed confirm never emits `ConfirmationClosed`.
- Limits: 100 questions of a kind, 32 handovers per question. Captures of the identical URL string join one question; a differing fragment does not (07-3). A join of a download compares addresses without the fragment.
- `pending_confirmations` and events show links with passwords hidden; the manager keeps the real ones.

## Headers and cookies

- `headers::is_allowed` refuses framing, hop-by-hop, `Range`, conditional, `Accept-Encoding`, `User-Agent` and `Proxy-*` headers, in `for_capture` and again in `to_map`, which also covers stored rows.
- `Cookie`, `Referer` and `Authorization` go once each; the dedicated fields win over `extra_headers`. A jar overrides `cookies`, and `extra_headers` may still supply a `Cookie` when neither gives one.
- Every value given to the engine is marked sensitive. Values with bytes under 32 or 127 are left out with a warning; non-ASCII passes.
- `for_another_site` keeps only `Accept` and `Accept-Language` (used by `refresh_link`).

## Sign-in expiry

- `forget_if_old`: for `Queued`, `Paused`, `Failed`, `Cancelled` rows added 7 or more days ago, drops every header but `Referer`, `Accept` and `Accept-Language`, and sets `forgot_sign_in`. It runs hourly, and in `start_run`. A failure asking for a fresh link then says why (`explain`).
- `forgot_sign_in` and `added_at` survive `refresh_link`. The link itself, with any password, is kept.

## `wirecatch_protocol::extension`

- `normalize_site`, `normalize_file_type`, `apply` of both patches have TypeScript ports tested against the case lists here.
- `check_sites` bounds what a patch names (1000 per list) before the lock; totals and `video_sites` are bounded later by `wirecatch_settings::validate`.
- `Debug` of `NewDownload`, `Header`, `CookieRequest` and `JarCookie` hides cookies, sign-in headers and passwords in addresses; serialization does not.
