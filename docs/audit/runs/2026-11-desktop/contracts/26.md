# Contract 26: notifications-and-tray

As the code behaves. Defects are in `chunks/26.md`.

## `wirecatch-shell::activity`

- `Activity::load(rows)` replaces all state; nothing in it counts as just ended. `Activity::apply(event)` returns `Ended` for a row whose status changed to `Completed` or `Failed`, and for a row first seen in that state. The same status again is not news; a failure after a retry is.
- Active means `Connecting`, `Downloading` or `Processing`. `speed()` adds only those.
- `format_bytes` is held to `packages/units/src/format-bytes.cases.json` and is the one Rust byte formatter, used across the desktop's interface. `tooltip(active, speed)` names the channel.

## `wirecatch-shell::teller`

- `Teller` holds no clock; callers pass `now` (tokio `Instant`). `ended` batches: the due time is `NOTIFY_BATCH` (3 s) after the first of a batch. Finished and failed batches are separate, and never mix.
- Finished rows are kept only for queues with `QueueNotify::EachDownload` (the default, also for an unknown queue). Failed rows are always kept. `queue_finished` gives a `Tell::Queue` only for other queues (`QueueFinished` itself is emitted for all). A `WhenDone` queue's failure is told twice by design (D52.3).
- A batch is a snapshot: later changes or removals of its rows do not affect it, and a row can appear twice.
- `Tell::telling(settings)`: `NotifyOnFinish` decides. `Nothing` silences failures too. In `Browser`, a failure stays until closed, and anything else stays `finish_notice_time`. `Window` is returned without checking that anything would be told; `finished::add` ignores empty lists.
- `start_notice` is `None` when `notify_on_start` is `Nothing`, and is independent of `notify_on_finish`. `told_as_started` is false for a media row whose source is not `Direct` (it was told by `MediaCaptured`).

## `wirecatch-shell::notifications`

- `Notification` is pure data: title, body, up to two buttons, click, `Lasts`, `important`. A click on the notification never opens a file; it is `Act::Show(Reveal)`.
- `chosen(notification, None | Some(place))` is the one mapping from a press to an `Act`, used by both system and browser. `Act::Retry` is offered only when the failure's fix is in `RETRY_FIXES` or absent.
- Only `started` and `video_added` are brief and not important. `video_added` has an empty `Reveal`.

## `wirecatch-shell::browser_notices`

- The extension gets words and button labels, never a download id. `pressed` maps id and place to an `Act`, or `None` for a forgotten notice.
- At most `KEPT_NOTICES` (32) notices of all kinds are kept. A forgotten notice's buttons do nothing, and it cannot be withdrawn.
- `ask` returns `None` when no connection listens. `answered` waits `ANSWER_WAIT` (1 s, `NOTICE_ANSWER_WAIT_MS`) and is false on timeout or when the notice was made outdated.
- `follow` withdraws a notice once all its ids are removed, or for `NoticeKind::Failed`, no longer failed. Notices with no ids (`plain`, `video_added`) are never withdrawn.

## `wirecatch-shell::system_notifications`

- `Notifier::show(notification, through_do_not_disturb)` never fails to the caller; failures are logged. `on_act` runs on any thread.
- Windows: the identity is registered in `HKCU\Software\Classes\AppUserModelId\<identifier>` with an icon file at start. `Show` runs on the calling thread. Handlers live for the last 32 toasts of each `Lasts`; a click after a restart does nothing (D52.5). `urgent` only from build 19041.
- Linux: one thread per notification, at most `MAX_WAITING` (16) waiting for a click; past that no buttons. Do Not Disturb is ignored (D64.3).

## `wirecatch-shell::tray`, `tray_queues`, `tray_speed`, `tray_proxy`

- Menu ids: `TrayAction::id`, `queue:<id>`, `speed:<bytes>|off`, `proxy:system|direct|<id>`. Each module's parser returns `None` for other ids. `limit_of` refuses 0.
- `perform` returns `AppUnavailable` for folder, pause and resume with no manager; `Open`, `NewDownload` and `Quit` work without one. `problem_tooltip` fits `MAX_TOOLTIP_CHARS` (127).
- `tray_queues::toggle` reads the queue's state at the click, not what the menu showed. `tray_proxy::switch` changes only `ProxySettings::proxy`.

## `wirecatch-desktop`

- `notices::start` must run before any `storage_failed` or `could_not` call (they read a global without checking); `main.rs` calls it during the app's start. `storage_failed` stays silent while the main window is open, since `notices_bar` shows it.
- `notices::watch` runs on the manager's runtime until the manager stops. It re-reads activity, queues and settings after a lag; what ended in the missed events is not told.
- `tray::start` does nothing but log when no icon can be built, and then `tray::exists` is false, so closing the window quits. Submenus are empty and disabled until settings load. The menu is rebuilt only when `Choices` change. Tray commands run synchronously on the interface thread inside the manager's runtime; failures are only logged.
