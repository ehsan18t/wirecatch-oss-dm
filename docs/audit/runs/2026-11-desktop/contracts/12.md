# Contract 12: app-updates

## `wirecatch-updates` (pure, no I/O)

- `Manifest::verified(bytes, signature, public_key)`: checks the Ed25519 signature with `verify_strict` over the exact bytes before parsing. Key and signature are unpadded base64url; surrounding space in the signature is trimmed. Errors: `NoKey` (the key does not decode, which includes the placeholder), `BadSignature`, `Unreadable` (bad JSON, an unknown field or enum value, or a `sha256` that is not 64 lowercase hex characters).
- `Manifest::file(system, arch, kind)`: the first match. `System::current` and `Arch::current` are compile-time.
- `newest(releases, current, prerelease)`: the highest semver strictly above `current`. Drafts never count. A pre-release counts only with `prerelease`, by GitHub's flag or by the version's own pre-release part. A tag that does not parse is skipped. `v` prefixes are stripped.
- `MANIFEST_FILE` is `update.json`, `SIGNATURE_FILE` is `update.json.sig`.

## `wirecatch_core::Manager`

- `check_app_update(current, kind)`: `Ok(None)` when no releases are configured or nothing is newer. Only the single newest candidate is considered: if it has no manifest or a bad signature, the result is `UpdateCheckFailed` and no older release is tried. The manifest's version must equal the tag's. `download` is `None`, while the update is still offered, when no `kind` was given, the manifest has no such file, the release has no such asset, or the asset's size differs. `page` comes from the unsigned list and is not checked.
- `fetch_app_update(download, progress, cancel)`: saves to `<data folder>/updates/<file.name>` at that exact path, replacing a finished file and continuing a partial one. Refuses before writing when the server's size differs from the manifest's. After completion it checks size and SHA-256 and deletes the file on a mismatch. A returned path was checked. Cancelling gives `UpdateCheckFailed("The update was stopped.")` and leaves the part and resume files. `cancel` is the caller's and is not tied to the manager's stop. Nothing removes files from the folder afterwards.
- All update requests use `PrivateNetwork::Block` and the app's proxy. Metadata reads are capped at 4 MiB.
- `ManagerConfig::with_official_app_releases` does not check for the placeholder key; the desktop's `app_update::set_up` does.

## `wirecatch_shell::updates`

- `install_kind()`: `Setup` on Windows; `AppImage` whenever the `APPIMAGE` variable is set, whichever program set it; otherwise `None`, which means offer the release page.
- `install(path, kind)`: the caller quits next. Windows: `ShellExecuteW` with `/SILENT /SUPPRESSMSGBOXES /NORESTART`, which elevates and blocks the calling thread until started. The setup closes a running copy through Restart Manager and starts the new version as the original user. Linux: copies over the path in `APPIMAGE` by rename in the same folder, then spawns it before the old copy has quit. `Deb` and `Rpm` return `SystemPackage`.

## `desktop::app_update`

- `Stage` is the single state, read by `notices_bar`, `settings/general` and `sidebar`. Check: one minute after start, then every 24 hours, only when `no_updates()` is `None`. A quiet check leaves `Available`, `InstallFailed` and busy stages alone, and a quiet failure returns to `Unchecked` and only logs.
- `install` on success moves to `Installing` and calls `lifecycle::quit`. Cancelling returns to `Available`.

## Release side

- `scripts/release/manifest.mjs <folder>`: lists only files named `<product>-<version>-<windows|linux>-<x64|arm64>` with a known ending, with the version from `config/product.toml`, in sorted order. It fails only when none match, so a missing platform does not fail it. The signed bytes are the exact file uploaded. It does not check the signature against the public key.
- `crates/updates/samples/update.json` is the one sample both languages read (D111.1). `node --test` in the JavaScript gate runs the script's test.
