# Contract 19: settings-and-proxies

As the code behaves, not as it is meant to.

## `wirecatch-settings`

- `default_settings()` and `default_queue()`: a fresh install, valid under `validate`.
- `validate(settings, queues, folders, suffixes)`: refuses out-of-range values and cleans lists (lower case, no dots, no duplicates; list counts checked before entries, except proxy exceptions, chunk 19-5). It does not check that `proxy.proxy` names a saved profile: callers call `proxy::check_use` first. No disk access, safe under the manager's lock.
- `within_limits` and `queue_within_limits`: for stored values, which skip `validate`. They clamp numbers, drop bad ignored and local sites, and reset unreadable app exceptions to defaults. They do not touch folders, `video_sites`, category rules or a queue's exceptions, so a stored bad one makes `validate` refuse every later change.
- `stored_local_sites`: also rerun when a newer suffix list arrives.
- `folder_for` and `type_folder`: a queue's own folder, else the first category rule for that category, else the default folder.
- `category_of` reads the last extension; `category_from_mime` is the fallback.

## Folders (`folders.rs`)

- `resolve`: no disk. Placeholders `{Downloads}`, `{Home}`, `{Documents}`, `{Videos}`, `{Music}`, `{Pictures}`, with plain name segments only; plain paths must be absolute, no `..`, no device or verbatim prefix (`\\?\UNC\` passes as a network path).
- `resolve_local`: for folders from a file. Adds refusal of network paths written plain and of protected folders, checked as written and through the real path of the nearest existing folder. Blocks on the disk; a network path is never contacted. A plain path that does not exist on this machine (`E:\Films` with no `E:`) is accepted and flagged outside the user's folders.
- `to_portable` is case-sensitive under Windows: a path differing in case from the known folder stays absolute.

## Settings files (`settings_file.rs`)

- `read_file` refuses over 1 MB. `export` does not enforce this: a file at the limits of every list could exceed it and not be importable (the comment on `MAX_SETTINGS_FILE_BYTES` says otherwise). Real files are far smaller.
- `parse`: only the exact current format; older and newer are refused with their own error. D6's "migrating older versions forward" does not exist.
- `localize` blocks on the disk and runs off the lock; `merge_localized` runs under it and changes nothing itself.
- Merge: the file's default queue updates this default queue whatever its name (chunk 19-2); other queues match by name ignoring case; proxies match by shown name; nothing is removed. Queue and global proxy references are remapped, and an unknown one becomes Global or System. Ignored sites without a host are dropped; other refusals fail the whole import.
- A failed folder falls back to `{Downloads}`, or to the default folder for rules and queues, as `Setting::Own`.
- Exports never hold a proxy password. They hold the proxy user name.

## Proxies (`proxy.rs`)

- `merge_password`: `Keep` holds only while `same_proxy` (kind, host ignoring case, port, user); empty means removal; a password needs a user. `same_proxy` ignores the name.
- `validate_settings_file` validates any profile, whatever its source, despite the name. Non-ASCII hosts are refused.
- `engine_choice`: pure apart from `ComputerProxy::Read`, which reads the environment and, on Windows, the registry, each time it is asked. `State::queue_proxy` calls it under the manager's lock when a run starts. A missing profile means the computer's proxy. SOCKS5 is always `socks5h`.
- `ytdlp_proxy`: `https`, else `all`, else `http`, `""` for direct, `None` to let yt-dlp read the system's. Ignores exceptions (chunk 19-4).
- `updater_proxy`: `https`, else `all`, else direct; never `http`.
- `from_system`: profiles without passwords; `socks4` and `socks4a` read as SOCKS5.

## Manager

- `change_settings`, `update_extension_settings`: patch, validate, apply under one lock. `apply_settings` does nothing when equal, and else saves, sets the global limiter, emits events and reconciles. Site lists in a patch are checked before the lock.
- `import_settings`: all or nothing; saved passwords survive only where `same_proxy` holds. Changed and new profiles lose `last_test` and are tested in the background.
- Saving, editing or deleting a profile never touches a running download. Deleting moves its users to the required replacement.
- `test_proxy_server` never saves a draft, sends the saved password only under `same_proxy`, and keeps the result only for an unchanged saved profile. Any HTTP answer through the proxy counts as `Works`.
- `run_system_proxy_reads` refreshes `State::system_proxy` every 30 seconds off the lock; it serves labels (`proxy_route`) only.
