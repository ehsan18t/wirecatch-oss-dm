# Contract 17: core-media-runs

How the code really behaves. Finding numbers refer to `chunks/17.md`.

## From a capture to a choice (`manager/media.rs`, `added_pages.rs`)

- `add_media_capture`, `add_video_page`, `read_answered_page` all end in `hold_media`, which puts a `MediaPending` in `state.media` under a `QuestionId`. Stages: `Analysing(token)`, `NeedsAddon`, `Ready { choice, plans }`.
- `add_media_capture` answers `AwaitingConfirmation` at once. The same link and kind joins the waiting question; once read, the same extractor and id folds into it (`join_same_video`) unless that would pass `MAX_HANDOVERS`. `read_answered_page` checks neither duplicates nor `check_room`.
- A question stays until `choose_media`, `dismiss_media_choice` or the last handover withdraws. `pending_media_choices` hides link passwords.
- `quiet` (no `MediaAnalysing`) is decided when it is held. Asking without a window is decided when it is read, from the settings then. A page waits at most 30 minutes for the add-on, checked only when the add-on arrives or the list is asked for.
- Read failure: a row `Failed` with Retry (`record_media_failure`, job with no format, so Retry takes the best through yt-dlp), or, for `page_otherwise`, the page as a plain file with `video_check: false`. Any read error counts as "no video", not only an unsupported page. If the row cannot be inserted this is only logged.
- `choose_media` takes the question off first (handovers `Confirming`), and on any add error puts it back. Choices are remembered only for `Picker::Person`.
- `keep_original` works only for `Failed` with `conversion_failed`; it drops output and sidecars and retries.

## The run (`media_run/`)

- `start_media_run` needs the caller to have checked limits. The first thing `run` does is look for `placing.done`; a match goes straight to `finish`, with no add-on needed.
- Work folder: `wirecatch_media::work_dir(entry.path())`, `<path>.wcmedia`. Derived from the row's current path each run, so changing the path loses it (17-2). The path of a media row is claimed but not checked on disk when added (`unclaimed_path`), so a folder already there is used (17-1).
- Files in it: `<role>.<ext>` and `<role>.done` (engine or HLS part), `media.<ext>` (yt-dlp), `sub-N.ext`, `subtitle-N.srt`, `cover.image`, `metadata.txt`, `joined.<ext>`, `output.<ext>`, `downloaded.json`, `placing.done`. Only `placing.done` records whose it is.
- `downloaded.json` is written once all parts and extras are there; every later attempt starts from it with no page read. It is not written atomically, and a bad one just means reading the page again, with `.done` markers saving the parts.
- Page formats: `ourselves` when every wanted format is present, has a URL and is `File` or `Hls`; else yt-dlp downloads the same selection, without the local network rule (documented) and without speed limits (17-4).
- Refresh: only an engine part's `address_gone` errors retry after `refresh_delays` with a fresh page read (401, 403, 404, 410, redirect and target errors). HLS parts never do (17-5). Parts run side by side and the end is decided after both: stopped, then failed, then refused.
- Extras never fail a video. Each small file is bounded (20 MiB subtitle, 10 MiB cover), held in memory, and checked by its first bytes.
- Network rule (`network.rs`): page local means `Allow`. `Website` is never local by name. Otherwise any local or unresolved format address is refused early and the rest run under `PrivateNetwork::Block`.
- A cancelled token turns any error into `MediaDone::Paused`.

## Placing (`placement.rs`)

- `finish` runs on `file_work`, marks the file, then `place`.
- `final_path`: if the file's own extension is a media one and differs from what follows the planned name's last dot, the planned name's last dot onwards is replaced (17-3). Non-media extensions are never taken.
- When `wanted` is a regular file: `Replace` renames over it; `KeepExisting` discards the new file and reports the old as the download; `Ask` returns `Placed::Asks` with no claim, the file stays in the work folder and `placing.done` is written; `KeepBoth` falls through. Otherwise the first free name from `name` on, skipping reserved names; at most 10,000 tries.
- Never replaced except by Replace: hard link where possible, else a rename after the check (FAT, exFAT).
- Any path other than the planned one is reserved; `run::complete` releases it.
- Subtitles go to `<stem>.<language>.srt`, always under Keep both, even beside a kept or replaced file; a failure is only logged.
- `MediaDone`: `Completed { path, bytes }` (path may differ from the row's), `Paused`, `FileExists(found)`, `NotConverted(error)`. `NotConverted` sets `conversion_failed` unless the run was asked to stop.

## For other chunks

- `Reserve` closure: `true` to reserve, `false` to release; it answers `false` once the manager is gone.
- `fake_media_tool` is only for tests; behaviour is driven by files in `fake-tools` next to the `addons` folder. It never reaches the network.
- `media_support.rs` holds the add-on releases, the signing key and event helpers used by `addons.rs` tests too.
