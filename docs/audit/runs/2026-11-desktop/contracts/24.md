# Contract 24: download-windows

## `wirecatch_shell::download_windows` (pure bookkeeping, no GPUI)

- `Registry` holds the open windows, the questions waiting for room, and the questions put aside. It returns `Step::Open` or `Step::Focus`; the caller does the work.
- At most `MAX_QUESTION_WINDOWS` windows show a `Shows::Question` at once. A window whose question already closed in the core still counts until the person closes it or it becomes a download. `Shows::Download` windows are not limited.
- `ask` clears put-aside and places the question, so the core moving a put-aside question on opens it again. `show_question` and `show_all` also clear it. `restore` respects it.
- `gone` puts a question aside; `failed` does not. `closed` removes a question from waiting and put-aside, and leaves its window open: the window says so itself.
- `restore` only opens windows that are missing. It does not tell open windows that their question moved on or closed (finding 24-9).
- `became_download` overwrites what a window shows, without checking whether another window shows that download (finding 24-6).
- A window keeps its label for life: `download-q<id>` stays the label after it becomes a progress window. Look windows up by `window_showing`, never by building a label.
- `place` always stays inside the given area unless the window is larger than it, then uses its top left. `fitted_height` never panics, returns between the smallest window and the screen or `MAX_WINDOW_HEIGHT`, and gives the smallest window for a non-finite height.
- `open_question_ids` and `open_questions` give each open question once, oldest first.

## `wirecatch_shell::finished`

- `FinishedBook::add` returns false for an empty list and changes nothing. A download listed before leaves its old place. Downloads told one by one join the newest group only if that group has no queue. Limits: `MAX_FINISHED_GROUPS` groups, `MAX_FINISHED_LISTED` rows in a group.
- `follow` replaces a listed row on `DownloadsChanged` and drops it on `DownloadsRemoved`, and drops a group left empty. A queue heading's counts are fixed when added, and are not changed by later rows or a heading's rows being truncated (D52.6).
- `queue_header` counts `Completed` and `Failed` in the rows it is given.

## `crate::download_windows` in the desktop app

- `init` must run before `follow`, `restore`, `show_all`, `show_download` and `finished::add`: they read the `Windows` global and panic without it.
- `follow` opens windows, and a first draw reads the library, so it must not run inside a library update. `Library::apply` defers it. `restore` runs inside the update and is safe only because it opens question windows, whose first draw has no question yet and so does not read the library. `finished::follow` only notifies and may run inside the update. A new path that opens a progress or complete window from inside a library update would panic.
- `finished::add` leaves out downloads with a progress window open, and opens the complete window without focus when closed. Closing the window forgets the whole list.
- Every window close, by the system, the title bar or `DownloadWindow::close`, goes through `gone`. Calling it twice for one label does nothing.
- `show_download` has no caller outside `follow` (finding 24-8).

## `DownloadWindow`

- Reads its question from the core with `api::question` and `api::earlier_download`; events only trigger a reload. While `busy`, a read that finds no question is ignored, so its own answer does not show the closed note.
- An answer returning `Some(id)` makes the window that download's progress if `show_progress_windows` is on, otherwise closes it; `later` and `None` close it. A refused answer shows the message and reloads. `answer_file_exists` returns `Some(id)` for every choice, Cancel included.
- The question's form stays until the download's row is in the library (D114.1), then `progress` clears the question and form.
- The window's height follows its content on every draw, so a manual resize of the height does not last.

## `MediaForm` and `media_output`

- `OutputChoice::apply` is the single place that writes the output choices into a `MediaSelection`, leaving out what the quality or video does not offer. An unchanged folder or queue is sent as `None`.
- `kbps_for` returns `None` for a format with no bit rate choices, and for audio that is copied when nothing else was wanted; otherwise a choice at or below what the source has, or the lowest offered.
- `size_for` uses bit rate times length only for audio only, otherwise the fit's size, falling back to the quality's.
- `MediaForm` sends its selection itself once the add-on is in. It decides the add-on is missing from `AddonState`, not from the core's check (finding 24-3).

## `RunRecord`

- Knows only what its window drew (`see` is called from render). Time counts only while `running`, with bytes arriving, between looks under `STALLED_AFTER` apart. Bytes going backwards resets the figures for the run. At most `MOST_SAMPLES` samples; `points` are in rising byte order and run from 0 to the asked end.
