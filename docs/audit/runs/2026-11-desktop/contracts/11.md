# Contract 11: media-addon

## `wirecatch-addons`

- `media_dir(data_dir)` is `<data_dir>/addons/media`. Inside: `installed.json` (`RECORD_FILE`), one folder per `ComponentId::as_str`, `.work` (`WORK_FOLDER`) and `cache` (`ytdlp_cache`).
- `Record::load`: a missing file or damaged content gives an empty record, and only a read error is `Err`. `Record::save` replaces the file whole and is flushed, and it creates the folder when missing (so a save after a removal brings the folder back).
- `tools(dir, record, check)` gives `ToolPaths` only when all three parts are recorded, every recorded file passes `safe_join` and is a regular file of its recorded size (and SHA-256 with `Check::Hashes`), and each program is one of its part's files. One failure anywhere gives `None` for the whole add-on. Blocks on the disk. It proves nothing against another program running as the same person (D38.2).
- `newer(a, b)` compares dotted numbers, a leading `v` ignored; anything unreadable is never newer. `outdated(record, wanted)` is true when a part is missing, for yt-dlp only when `wanted` is newer, and for the others when the version differs in either direction.
- `checksum_for(list, file)` matches the exact name and skips a line whose digest does not parse.

## `archive`

- `open_release` shares read only on Windows. `sha256_of` hashes from the start of the open file.
- `unpack(component, file, empty_stage)` writes only the manifest's files to the manifest's paths. A file not named is skipped. An entry under a named file that is not a plain file, a tar entry named twice, a missing file and a file past 1 GiB are errors. It leaves partial files in `stage` on error, and the caller discards them.
- `is_safe_relative`, used through `safe_join`, is the check of a manifest or record path (D38.3).

## `manifest` and `signature`

- `AddonComponent` from `new` is valid: at least one file, a plain release has exactly one, safe unique targets, and the program is one of the files and executable. `official` builds its parts directly and a test holds them to the same rules. `ReleaseFile` size is never 0.
- `Sha256Digest` compares as bytes and writes lower-case hex. `Fingerprint` is a full fingerprint in upper case.
- `verify_detached(key, data, sig)` is `Ok` only when the armored key has the pinned fingerprint, its bindings verify, and a binary or text signature in `sig` verifies `data` with the primary key. Subkey signatures do not count. It blocks on CPU.

## `Manager` (core, `manager/addons`)

- `install_addon` and `update_addon` are the same call. It hashes every file first, runs off the async threads, and returns before the install ends; results arrive as `UiEvent::AddonsChanged`. It does nothing when an operation is running, including a quiet one, which then stays quiet.
- An install's plan is every part when `tools` is `None`, otherwise the parts `outdated` picks. With `tools` `None` the yt-dlp is the pin or a mature release newer than the installed one, never the installed one (11-1).
- All downloads use `PrivateNetwork::Block` and the app's proxy and limits, follow redirects, must announce a size no larger than the release's size plus 4 KiB, and resume from `.work/<part>-<version>.download`.
- Parts are staged in parallel. One failure stops the others and nothing from that run is swapped in. The swap then runs part by part, saving the record after each, so a failure in the swap can leave earlier parts new and the record matching them. A part lost in the swap is removed from the record and sets `part_lost`, which is shown even for a quiet or stopped install.
- `cancel_addon_operation` waits for the end, then deletes `.work` when the add-on had working tools, and the whole add-on folder when it did not. The media waits are not failed by a stop; they stay `NeedsAddon`.
- `remove_addon` is refused with `WrongState` while a page is being read or a media job is running. Otherwise it stops any install and deletes the folder. Neither it nor an install knows of an update check in flight (11-2).
- `check_addon_updates` does nothing unless tools are present. It always stamps `last_update_check`, even after a failure, and fails with `UpdateCheckFailed` only for an unreachable list or a bad signature. It replaces `ytdlp_releases`, and starts a quiet install when `auto_update_addons` is on and the plan is not empty.
- `run_addon_updates` looks hourly; a check is due at most once per 24 hours, only with `auto_update_addons` on and tools present.
- A found yt-dlp must be at least 48 hours old by the release list's `published_at`, come from exactly `<release folder><tag>/<name>`, have a checksum from a list signed by the pinned key, and answer `--version` with exactly its tag. A wrong answer refuses it until the app restarts: `Refusal` is held in memory only. A run that fails or cannot start is an ordinary failure, and its download is kept.
- After the manager's install ends: `media_addon_ready` runs when tools are present, and `media_addon_failed` when they are absent and the install was neither stopped nor quiet.

## Programs and pins

- `MediaAddonSources::official()` pins yt-dlp, ffmpeg (from the `addon_files` repository, D80) and Deno per system. ffmpeg's install is `ffmpeg` plus its seven libraries; `ffprobe` is not installed, and no code in media, streams or core uses it.
- `cargo run -p wirecatch-core --example ffmpeg_release` prints `<url> <sha256> <path in archive>` on one line, for CI.
