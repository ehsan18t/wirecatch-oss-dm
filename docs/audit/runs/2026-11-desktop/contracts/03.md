# Contract 03: saved-state

As the code really behaves. Findings are in `chunks/03.md`.

## wirecatch-store

- `Store::open(dir, on_failure)` blocks on the disk. It makes `dir`, restricts it to the owner, takes the `<db>.lock` file lock (waits `LOCK_WAIT`, 2 s, then `AlreadyOpen`), deletes copies older than `KEEP_COPIES_FOR` (720 h, by file modified time), runs `integrity_check`, sets WAL with `synchronous=NORMAL` and `secure_delete=ON`, migrates, loads, and starts the `wirecatch-db` thread.
- Open errors: `AlreadyOpen`, `TooNew`, `Database`, `File`. Only `SQLITE_CORRUPT` and `SQLITE_NOTADB` count as damage: the database and its `-wal`, `-shm` move as a whole to `<db>.damaged-<unix ms>` and a new list starts (`Recovery::Damaged`). A cell that fails type or UTF-8 conversion is not damage and fails the open (03-1).
- `.bak-v<found>` is a best-effort `VACUUM INTO` copy before an upgrade. Each migration runs in its own transaction with `user_version`. `MIGRATIONS` is append-only.
- `Snapshot.settings` is `None` both on a first start and when the stored value cannot be read (03-2). Unreadable queues and proxy servers are left out, with no recovery reported. Unreadable `last_ids`, batches and logins read as empty.
- A download row with an unknown `status` or `category` stays in the table, hidden from the snapshot, with its sign-in removed, and is counted once in `Recovery::UnreadableKept`. Its id is not in the snapshot, so `last_ids` is what protects it from reuse.
- Other repairs at load, written back at once: a negative count (`ValuesReset`), a damaged origin (replaced by `forgotten_origin`, not reported). Damaged media reads as `MediaJob::Unreadable` with an unfinished row turned `Failed`, in the snapshot only, until the row is next saved.
- `not_private` carries the reason the folder could not be restricted; failures on single files are only logged.

## Writes

- All `save_*` and `delete_downloads` calls are non-blocking sends on an unbounded channel, applied in send order and committed together when queued. They return nothing. After close they log and do nothing.
- `save_progress` updates `done` and `total` of an existing row and creates none.
- `save_queues` replaces every queue, in the given order. `save_settings`, `save_last_ids`, `save_batches`, `save_proxy_logins`, `save_proxy_servers` replace their whole value.
- Failure handling: a failing batch retries after 50 ms, 250 ms and 1 s if `may_pass_later` (busy, locked, I/O, full, read-only, cannot open), then each write is tried alone. Writes that may pass later are kept in order, with later writes to the same row held behind them, and retried with the next batch or after 5 s. Writes that can never pass are logged and dropped (03-8). Past `MAX_KEPT` (10,000) only each row's latest stays, then the newest.
- `on_failure` runs on the database thread, only when a failing batch held no kept writes. Nothing reports recovery (03-3, 03-4).
- `close(timeout)` saves what was sent before it, gives kept writes one more try, closes the connection, releases the lock, then answers. A timeout only logs: the thread goes on. Each write tried against a held lock can take `BUSY_TIMEOUT` (5 s). Dropping every handle closes too, without anyone waiting (03-7).
- A power cut can lose the latest commits (`synchronous=NORMAL`) but not earlier ones. Restart logic must not assume the last status or progress was saved.

## wirecatch-records

- Saved types: `Origin`, `StoredMedia`, `MediaJob`, `OutputJob`, `Pick`, `FormatId`, `StoredBatch`, `Outcomes`, `Logins`, `SavedProxyServer`.
- `FormatId` from text accepts only ASCII letters, digits and `_ . - =`, at most 100 bytes; a stored id outside that makes the whole `StoredMedia` unreadable. `Default` gives an empty id that `try_from` would refuse. `selector()` is quoted and exact.
- `MediaJob::Unreadable` must never run. `job: None` means a direct file that downloads as any other.
- `without_sign_in` returns `None` when nothing was removed.
- `OutputJob::needs_pass` is true unless `original` is set and nothing goes inside the file.

## wirecatch-files

- `whole_file::replace(dir, name, bytes)`: writes `<name>.tmp`, flushes, renames over `name`, and on Unix flushes the folder. A failure before the rename leaves `name` as it was and may leave the `.tmp`. On Unix a failed folder flush returns an error after `name` has been replaced. Not safe for two writers of one name at once. New files take the folder's default access, so it is not for secrets outside a private folder.
- `owner_only::restrict(path)`: Windows sets a protected access list granting the process's user full control, inherited by new children and pushed to existing ones. Unix uses 0700 or 0600 and follows symlinks. The `testing` feature adds `refuse_on_this_thread`; only dev-dependencies turn it on.
- `discard::file` and `discard::dir` block, treat a missing target as done, and log any other failure.
- `zone::mark(path, host_url, referrer)` is Windows only and best effort: it never creates the file, follows a rename after the open, and cannot report failure. `HostUrl` loses its query; `ReferrerUrl` keeps it. Both lose credentials and fragment and are cut at 2048 bytes.
- `FileError` is a person-readable text with the path. `with_suffix` appends past any extension.
