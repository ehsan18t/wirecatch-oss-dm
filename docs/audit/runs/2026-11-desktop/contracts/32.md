# Contract 32: cli

The `wirecatch` binary (`crates/cli`, package `wirecatch-cli`). No library API; other crates and the fault tests use it as a process. It reaches only the engine, logging and product crates, never core, store or the app (D13).

## Invocation

`wirecatch URL [-o DIR] [-n NAME] [-c 1..=64] [-H "Name: value"]... [--http3] [--proxy URL | --no-proxy] [-q]`

- `URL`: must parse and pass `wirecatch_engine::url::is_supported` (http, https, ftp, ftps, ftpes). A refused link is repeated in the error only when it holds no `@`.
- `-o`: folder, default the current one. The engine's folder path is always used, never `exact_path`: a finished file is never replaced, a taken name gets ` (1)`, and an earlier run continues only under the unnumbered name with the same URL (contract 01).
- `-n`: passed as `file_name`, which the engine sanitizes without saying so.
- `-c`: default is the engine's default; the upper bound is held equal to `wirecatch_engine::MAX_CONNECTIONS` by a compile-time assert.
- `-H`: refused on FTP links. Values are checked, and errors never repeat them. No header is filtered, so `Range` and the like reach the engine as given.
- `--http3`: refused unless built with the `http3` feature. Ignored without error on FTP.
- `--proxy`: trimmed, must parse with a host, scheme one of http, https, socks4, socks4a, socks5, socks5h (no scheme means http). Becomes `ManualProxies::all`, with `exceptions` from `NO_PROXY`, else `no_proxy`. System exceptions are not read. `ftp_direct` is never set. Neither flag: `ProxyChoice::System`.
- Never set: `allow_insecure_redirects` (false), `private_network` (the engine's default, `Allow`, so local addresses work), `if_exists`, buffer and timeout options.

## Output

- stdout: one summary line when the download ended without an error ("Saved...", "Paused..."). Nothing else.
- stderr: the progress bar unless `-q`, "Pausing..." on the first Ctrl+C, warnings and up from logging (`WIRECATCH_LOG` chooses), and errors as anyhow prints them (`Error: ...`, with "Caused by"). Engine error text can hold a link's query string (contract 02), not its password.
- Log file: `release_folder()`, or `WIRECATCH_LOG_DIR`.

## Exit status

- 0: file complete.
- 1: any engine error, a request refused by `build_request`, or stdout failing with anything but a broken pipe.
- 2: clap usage errors.
- 130: `Outcome::Paused`, an `Outcome` variant it does not know, or a second Ctrl+C (immediate `process::exit`).
- Known gaps: Ctrl+C before the server answers exits 1 (32-2); a closed stderr pipe at Ctrl+C aborts (32-3). Only Ctrl+C is handled: other signals and closing the console end the process at once, leaving the last checkpoint.

## Not guaranteed

The "Run the same command again" line is printed for every pause, including those that restart from zero (32-1). Remaining size on a pause is meaningless when the size is unknown (32-1).
