# Contract 20: logging-and-secrets

## `wirecatch-logging`, feature `setup` (default)

- `start(name, default_filter) -> Logging`: installs the subscriber and the panic hook, once. A second call keeps the first and says so on stderr. `WIRECATCH_LOG` chooses lines; a bad value falls back to the default with a warning.
- `Logging::write_to(Option<&Path>)`: names the log folder. Lines before it are held up to 256 KiB (lines past that are counted, not kept). The folder and file are made with the first line. `None`, or a failure, means stderr only, and what was held is lost.
- `folder_in(data)`, `channel_folder(channel)`, `release_folder()`: `WIRECATCH_LOG_DIR` wins over all three. The bridge and CLI use `release_folder`, the app `channel_folder` or `folder_in` its `WIRECATCH_DATA_DIR`.
- Files: `<name>.log`, moved on at 5 MiB, 3 old files. If it cannot move (a reader without delete sharing), lines stay and the move is retried every 1/16 of the limit; past twice the limit the file is emptied with a note. If emptying fails too, it keeps growing.
- Several processes of one binary may share a file. Appends do not overwrite; a writer follows a moved file within 16 lines, or on every line past half the limit.
- Lines are written synchronously to stderr and then the file, under one mutex, with no background thread: blocking on async tasks is the accepted exception (D40.2). Failures to write a log never reach the caller; the first is said once on stderr.
- Panics: the hook replaces the standard report, redacts it and writes it to the sink directly, so no filter silences it. A thread that panics holding the file reaches stderr only. Nothing is buffered, so the report survives `panic=abort`.

## `wirecatch_logging::redact` (available without `setup`)

- `text_for_log(&str) -> String`: four passes: link user information, query values and fragments of links and of a word starting with `/`, scheme credentials with JWTs and service keys, then values of secret names (`:`, `=`, `%3A`, `%3D`, quoted, escaped, tuple, `Debug` field, bracketed, tag, command-line flag, header objects both ways). Never panics; linear in length. It may grow a line, at most about double.
- `text_for_display`, `url_for_display`, `optional_url_for_display`: only a link's user information. Queries stay.
- It is a net, not permission: not hidden are a token in a link's path, a scheme-less link's query, opaque runs nothing names, and `user:pw@host` without a scheme. A link broken by an apostrophe keeps what follows it (20-1). Text naming a secret word before a colon loses the rest of its line, also when the word is part of a file name or host (20-2).
- Every event's fields are redacted as recorded, and the finished line again. A field whose name marks a secret prints `name=***` whatever its value. `HIDDEN` is `***`; redaction is idempotent on it.

## `wirecatch_protocol::secrets`

- The one definition of what a secret is, for the log and the extension: `is_secret_name` (segments split at `-`, `_`, `.` and camelCase, each a word or an ending), `names_a_password`, `looks_like_a_credential`, `is_service_key`, and the generated word lists and `HIDDEN`.

## `wirecatch_protocol::secret`

- `Secret`: serializes as the plain string, `Debug` prints `"***"`, no `Display`, read with `expose()`. Serializing a struct that holds one writes the secret.
- `Link`: an address as a plain string on the wire. `Debug` drops its sign-in (`"ftp://h/a" (sign-in ***)`) or prints `"***"` when it cannot parse and holds an `@`. `Debug` keeps the query; only the log's redaction hides it.
- `Address`, `OptionalAddress` (crate-private): the same `Debug` for a `&str`.

## `wirecatch_test_support::redaction`

- `redaction_cases`, `rule_cases(name)`, `wrappings(text)` read `data/redaction.json`, the one file of samples, also loaded by TypeScript. A new secret form is added there, in pieces when shaped like a provider's credential.
