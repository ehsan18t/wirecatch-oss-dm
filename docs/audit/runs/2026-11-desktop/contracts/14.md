# Contract 14: stream-manifests

How `wirecatch-streams` reads HLS and DASH text and turns a choice into a plan, as the code behaves. Chunk 15 (download) consumes the `Plan`.

## Entry points

- `Source::load(&Fetcher)`: fetches at most 8 MiB, decodes lossily as UTF-8, detects the format by content, then `Content-Type`, then extension. Neither gives `Error::NotAStream`.
- `Source::info`: returns `StreamInfo`. An HLS master also fetches its best quality's media playlist for `duration` and `live`; that one playlist's format is reported for every track of the master, a forecast only. DRM is not reported here: it is refused at `plan`.
- `Source::plan(self, fetcher, video, audio)`: returns a `Plan` or refuses before any segment is fetched: `Error::Live`, `Error::Drm`, `Error::Unsupported` (several DASH periods, HLS encryption other than AES-128), `NoSuchTrack`, `NothingChosen`, `Manifest`, `TooLarge`, `TooManySegments`. Template and list expansion and `sidx` reading happen here, for the chosen tracks only.
- `select::from_master`, `from_media`, `from_mpd`: a pure pick. `StreamInfo::extension` uses the picks recorded in `AutoPicks`, which come from the same code.

## What a Plan guarantees

- `Plan.tracks` is not empty, in order video then audio, at most one of each. `Track.role` is `Audio` only for a track picked as audio; an audio-only HLS variant picked when no variant has video has role `Video`.
- Each `Track.pieces` holds at most `MAX_SEGMENTS` (200,000) pieces, init sections included, and at least one non-init piece. Every `Piece.url` is `http` or `https`, at most `MAX_URL_LEN` (8 KiB). A track's piece addresses total at most `MAX_TRACK_URL_BYTES` (64 MiB). `Encryption.key_url` is checked for scheme and length but is outside that total.
- `Piece.range` is never empty and is start inclusive, end exclusive. It may lie beyond the real file: nothing checks it against a size.
- `Piece.init` pieces are in join order: HLS emits an init section before the first segment using it and again whenever it differs from the one before. A `sidx` file's init piece is `0..first media byte`, the index included.
- `Encryption.iv` is the explicit IV or the media sequence number. The init section's key is the one in force where its `EXT-X-MAP` appears.
- `Track.codecs` holds the names the variant or representation lists, `None` for each it does not know (subtitle formats included); empty for HLS renditions and single media playlists, which name none. Not limited to the tracks actually downloaded: a muxed variant's list names its audio too.
- Addresses are not vetted for the local network here; the `Fetcher` applies `PrivateNetwork` when they are fetched.

## Fingerprint

`Plan::fingerprint` (FNV-1a, stable across runs) covers track count, roles, piece count, each path, each query name, query values except signing parameters (`is_signing_parameter`), ranges, IVs and the init flag. It leaves out hosts, signing values and key addresses. So a refreshed signed link keeps its segments, while a token in the path starts over. Two videos with identical paths and piece counts on different hosts share a fingerprint, by design.

## Track ids

`track_id` derives ids from what a track is, so they survive reordering: `v-<hash>` for variants, `r-<hash>` for renditions, `d-<id>` for named representations, `dh-<hash>` for unnamed ones, `v-playlist` for a single media playlist. Twins get `~n`, by list order, the one case where a reorder can swap them. A DASH id repeated with different attributes gets `~<hash>`. A variant's id changes when its path, non-signing query, bandwidth, size, frame rate, codecs or audio group change; the choice then fails with `NoSuchTrack`, which `media::describe` words with a refresh-link fix.

## Automatic choice

HLS video: highest `BANDWIDTH`, then picture size, among variants that are not audio-only; else among all. HLS audio with video: the variant's group, among renditions with a `URI`, default then autoselect then first. HLS audio alone: renditions with a `URI` by default and autoselect, else the best audio-only variant. DASH: `Role value="main"`, then bandwidth, then picture size, by kind. Text tracks are never downloaded.

## Limits while reading

8 MiB of text; 16 MiB of `sidx`; 4096 DASH representations; 8 MiB of DASH name text; HLS master: 128 MiB of addresses and 800,000 entries, the second out of reach for a fetched playlist. No limit on the number of HLS qualities below that, on HLS key addresses, or on one address while a template is filled in (findings 14-1, 14-2, 14-3).

## Types other chunks use

- `codec`: `Codec`, `VideoCodec`, `AudioCodec` and `Container` are the one policy for streams and pages (D24, D31). `Container::for_copy` picks MP4 or M4A only when every listed codec fits, else Matroska; no codecs listed tries MP4, and `fallback` gives Matroska. The enums are deliberately exhaustive.
- `extension`: `is_media` (a file may be saved with it), `is_replaceable` (media or stream part).
- `error`: `Error` is `#[non_exhaustive]`, and its messages are written to show to a person. `Manifest` keeps only the host; `Key` keeps the whole address. `map_engine` turns `Cancelled` and `PrivateNetwork` from the engine into this crate's own variants.
- `model`: `StreamRequest` has no default network rule. `StreamProgress` holds relaxed atomics, with no ordering between counters.
