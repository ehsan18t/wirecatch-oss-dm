# Contract 22: app-start-and-quit

## Start order (`crates/desktop/src/main.rs`)

Logging, `--remove-start-entry` (acts and returns, before the elevation check), elevation refusal (release builds only), runtime, `bridge::bind`, then `Backend::start` and GPUI. Every window, the tray and the updater run after `cx.set_global(backend)`. A bind error other than `AlreadyInUse` is logged and the app runs with no endpoint; the database lock is then the only single-instance guard.

## `wirecatch_shell::host`

- `Core` opens the manager once in a `OnceCell`. `Core::preparing` runs its closure on a blocking thread. A failed open is kept: every later `opened()` or `manager()` answers the same error until restart.
- `Unopened.another_copy` is true only for `StoreError::AlreadyOpen`, which `Store::open` gives after waiting `LOCK_WAIT` (2 s).
- `data_dir` honours `WIRECATCH_DATA_DIR` first, otherwise moves the roaming folder to the local one when the local one has no database file. Because the listener makes the local folder first, the app's path is normally the merge: other entries first, the database copied last, the old folder deleted after. On failure the old folder is used, and entries already moved stay moved until the next start finishes the move.
- `DEV_BUILD` is `cfg!(debug_assertions)` and `CHANNEL` follows it.

## `Backend` (`crates/desktop/src/backend.rs`)

- `Backend::run` waits for the open and gives `Err(Unopened)` when it failed. `Backend::now` does not wait.
- `Backend::stop` is the whole of stopping downloads. It waits at most `OPEN_PATIENCE` + `QUIT_PATIENCE` (10 s + 15 s) and does not end the process (finding 22-1).
- The endpoint is served only after the manager opens: a client can connect during the open, but gets no answer until then. If the list failed to open, every request gets `AppUnavailable`, hello included.
- `AlreadyOpen` shows a message and calls `process::exit(0)` from a task, whatever the launch asked for.

## Quit (`crates/desktop/src/lifecycle.rs`)

- `lifecycle::quit` is the one quit, safe to repeat. It sets `Quitting`, removes the tray and all windows at once (bypassing `closing` steps), and calls `cx.quit()` after `Backend::stop`.
- `is_quitting` means nothing may open. `main_window::bring_up` turns any request into `start_again_later`: the process starts a new copy after freeing the endpoint, with the links as its arguments; other requests become a plain start.
- `closing::on_close` is the one way to add a step before a window closes, and `closing::close` is what a title bar's Close button calls. A step returning `false` keeps the window.
- `quit::keeps_running`: `None` settings (opening, or failed to open) count as close to tray.

## `launch`

- `Launch::from_args`: `background` is exact `--background` after the program name. Links are the arguments with one of the five schemes, no control characters, at most 8 KiB, at most `MAX_OPEN_LINKS`; other arguments are ignored. A link overrides `--background` for `shows_window`.
- `hand_over`: hello, then `open_links`, or `show_window`, or nothing. Each answer waits `ANSWER_WAIT` (5 s). The Add dialog does not accept everything `Launch` does (finding 22-2).

## `autostart`

- The entry is written again on every start while wanted. `TurnedOff` with no fresh choice turns the setting off; `sign_in::follow` then sees the change and removes the entry too, so "leave the entry" in `Action::TurnSettingOff`'s doc holds only for a moment.
- `--remove-start-entry` removes the entry of the account that runs it.

## `bridge` (shell) and `bridge/src/install`

- `bridge::bind` gives `AlreadyInUse` when another copy holds the endpoint. `serve` and `serve_unavailable` own their connections: aborting the task ends them and frees the listener and key lock. At most 64 connections at once.
- `register_on_start` runs in a thread on every start of a release build, after the data folder has moved. It never registers a bridge in a temporary folder, and under an AppImage it registers a private copy in `<data>/bin` (0700, with a launcher script). A failure is only logged.
- `install` writes only what differs. `install_for_user` under a covering machine registration removes this copy's per-user registration and those of bridges that no longer exist, and leaves those of another copy that exists, which then hide the machine one. `uninstall` removes a key or manifest only if it holds what this copy writes.
- A report's failures go to stdout and the exit code only (finding 22-5).
- Every copy for one Windows user writes the same manifest paths, under the release data folder, whatever its channel.

## `elevation`, `message_box`

- `decide` refuses only `Elevated`. `AlwaysAdministrator` and an unknown state continue.
- `message_box::show` blocks until closed on Windows and only logs elsewhere, so `say_already_running` and `say_before_exit` are silent on Linux.
