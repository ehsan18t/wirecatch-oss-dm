# Contract 29: packaging-and-release

## `scripts/package.mjs`

- `node scripts/package.mjs [--target <triple>]` runs `gate.mjs release-build` (`product`, placeholders only warned), builds `INSTALLER_CRATES` (`wirecatch-desktop`, `wirecatch-bridge`) in release with `--locked` and no feature, and writes to `target/packages`. Real use is for the build machine's own architecture (see 29-3).
- Names, which `scripts/release/manifest.mjs` `describe` parses: `<name>-<version>-windows-<arch>-setup.exe`, `<name>-<version>-linux-<arch>.{deb,rpm,AppImage}`; `arch` is `x64` or `arm64`.
- Windows links the C runtime statically through `RUSTFLAGS` (D33). The Linux tools are pinned and their SHA-256 checked on every run.

## What an install holds

- The app and the bridge always sit in one folder under their product names: `{app}` on Windows, `/usr/bin` on Linux, `usr/bin` inside an AppImage.
- `THIRD-PARTY-NOTICES.txt`: beside the executables on Windows; `../share/licenses/<slug>/` from the executable on Linux and in an AppImage. `crates/shell/src/host.rs` `notices_path` relies on this.
- `.desktop` file and icon are named after `channels.release.identifier`, and `StartupWMClass` is that identifier.
- An AppImage's `AppRun` sets `LD_LIBRARY_PATH` for the app and all it starts (see 29-2), and carries `libxkbcommon.so.0`, `libxkbcommon-x11.so.0`, `libxcb-xkb.so.1`.

## What the installers run

- Setup: `wirecatch-bridge install --all-users` after installing, a message box when it fails (hidden by `/SUPPRESSMSGBOXES`). Restart Manager force-closes programs using files it replaces. A silent run starts the app as the original user by itself; a wizard run offers it. `crates/shell/src/updates.rs` relies on the first and on `/SILENT /SUPPRESSMSGBOXES /NORESTART` asking nothing.
- Uninstaller: `wirecatch-bridge uninstall --all-users`, `wirecatch-bridge uninstall`, `wirecatch-app --remove-start-entry`, before files go. It closes nothing (see 29-1). `crates/shell/src/autostart.rs` has a test that the script names the flag.
- `prerm.sh`: on deb `remove`/`purge` or rpm `0`, runs `wirecatch-bridge uninstall` as each user with uid 1000 to 59999 and an existing home, ignoring failures; nothing on upgrade. Generated from the template at packaging time.

## `scripts/notices/`

- `installerPackages(triple)`: registry and git crates in `cargo tree` for both installer crates, normal and build edges. Workspace crates count as the app's own code.
- `renderNotices({ title, packages })`: same text for the same packages, identical texts shown once, the Public Suffix List always listed. Throws `GateError` when a licence is outside `deny.toml`'s allow list, or has no text in the package or `config/licenses`. Texts may be over-included, never knowingly dropped: a declined text goes only when its file is plainly named and it is recognised.
- `shippedTargets()` and `allowedLicences()` read `deny.toml` by hand. `npm.mjs` is the extension's entry point.

## `.github/workflows/release.yml`

- A `v*` tag builds on four runners, checks the x64 Linux packages only (29-4), builds the extension, then `draft` runs `gate.mjs publish`, requires the tag to equal `v<version>`, signs `update.json` with `UPDATER_PRIVATE_KEY`, and creates a draft release, flagged pre-release when the tag holds `-`. A hand run off a tag ref skips `draft`.
- `scripts/ci/linux-package-check.sh deb|rpm|appimage FILE APP NOTICES` runs as root, and exits non-zero unless notices exist, `ldd` is clean (packages only), the app runs until stopped and registers the bridge, and removal unregisters it (packages only).
