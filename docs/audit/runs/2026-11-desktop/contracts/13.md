# Contract 13: program-running (`wirecatch_streams::process`)

The only runner of the add-on's programs (D31). Used by `crates/streams/src/ffmpeg.rs`, `crates/media` (`ffmpeg`, `ytdlp`) and `crates/core` (add-on version checks).

## API

`run(program, args, dir, options, cancel, on_line) -> Result<Ran, RunError>`

- `RunOptions::lines()` passes both outputs to `on_line`; `RunOptions::collect()` collects standard output whole and passes only standard error. Added with `with_timeout`, `with_idle_timeout`, `with_environment`, `watching`.
- `Ok(Ran)` means the program ended by itself, whatever its exit code: check `Ran::success()`. `status` is `None` when waiting for it failed, which counts as failure.
- `Err` is `Start`, `Cancelled`, `TimedOut { limit, stderr }` or `Stalled { quiet, stderr }`.
- Constants: `STALL_TIMEOUT` 5 minutes, `MAX_STDOUT` 64 MiB, `STDERR_TAIL_BYTES` 8 KiB, `MAX_REASON_CHARS` 300.

## Guarantees

- Started with an argument vector, in `dir`, standard input null, no console window on Windows. Every inherited variable whose name starts with `PYTHON` (any case, valid Unicode names only) is removed before `environment` is applied. `Debug` of `RunOptions` shows variable names only.
- Windows: starts suspended, is put in a job with kill-on-close, then resumed; failing that it is killed and the result is `Start`. Nothing it starts can leave the job.
- Unix: leader of a new process group. `killpg` is sent at most once and only before the leader is reaped. Each running program holds one blocking-pool thread on `waitid`.
- The group is killed on cancel, time limit, stall, dropping the future, and as soon as the leader exits, so a program may not leave anything running on purpose.
- Lines: at most 16 KiB each, cut at a character boundary, invalid UTF-8 replaced, line ends trimmed, the rest of a long line read and discarded. A line ends only at `\n`, so callers must make programs write `\n`-ended progress (`--newline`, `-progress pipe:1 -nostats`), or `\r` progress never reaches `on_line` or resets the idle limit.
- `on_line` is called from the run's own loop: a slow one holds up the timers and, through a queue of 64 lines, the readers. It receives raw text with secrets. Only `StderrTail` is redacted.
- Collected standard output: at most `MAX_STDOUT`, the program's pipe drained to the end past it, `stdout_truncated` set.
- `StderrTail`: newest lines within 8 KiB, each redacted before storing. `error_line` is the last line containing the exact text `ERROR`, else the last line, which may be blank. `summary(n)` skips blank lines; `reason()` is `error_line` or the exit status. All are for a person or the log; `for_a_person` cuts to 300 characters.
- Logged: failed, timed-out and stalled runs as warnings with the redacted tail. A cancelled run is not logged. Arguments are never logged.

## Timers

- `timeout` covers the whole run from just after the start, including the grace below.
- The idle limit starts just after the start and is reset by any line, except standard output in collect mode. At expiry `watch` is looked at: size and latest write time of the file, or of the files straight inside the folder. A change resets it, so a stopped program may last up to twice the limit.
- An idle limit is meaningless with collect mode unless the program writes to standard error. No caller combines them.
- `OUTPUT_GRACE`, 2 seconds after the leader exits and the group is killed: reading stops after it. Callers get a normal `Ok` then, with lines dropped, and in collect mode empty standard output (finding 13-2).

## Not guaranteed

- On Unix a program that left the group (`setsid`) is not killed.
- Nothing kills a Unix group when the app itself dies (`docs/ROADMAP.md`); on Windows the job does.
- After a dropped future or an abort, reader tasks can stay until the outputs close, only when something outside the group holds them.
- Waiting after a kill has no limit (13-S1).

## Test tool

`crates/streams/examples/fake_program.rs` is used only by `crates/streams/tests/process.rs`. That test needs the examples folder beside the test binary's parent, so `cargo test -p wirecatch-streams` works and a test built alone fails loudly; this is what made 19 tests fail in the coverage run in `tools.md`.
