# Contract 05: core-final-path

How the code really behaves. Finding numbers refer to `chunks/05.md`.

## `naming::Claimed`

- A set of path keys, with no owner. Keys are the path string, lowercased on Windows; there is no other normalisation, and `KnownFolders::resolve` supplies consistent separators.
- `insert` marks a path taken. `reserve` takes it for a moment and counts it apart. `settle` makes a reservation a download's own. `release` and `remove` are the same operation.
- Intended invariant: every non-completed row's path is claimed, and a claim plus reservations equal the non-completed rows plus stranded paths. Checked by `State::assert_consistent` in debug builds only.
- Not guaranteed: two downloads sharing a path after Replace (05-1), and a claim surviving when a finished row at that path is moved or removed (05-13).
- A finished file holds its name on disk, not by a claim.

## Name functions (`naming.rs`)

- `file_name`: preferred name, else the link's, sanitized. Refuses names ending in `.wcpart` or `.wcstate` (any case) with `CoreError::Invalid`.
- `settled_name`: person's choice (refused if it looks like an engine file), else the server's name if it differs from the link's and from `download`, else the provisional name, else the suggestion. A server's or browser's engine-like name gets `_` appended instead of an error. The provisional name may already carry ` (1)` (05-2).
- `unique_path`: first free name on disk (file, part, resume) and unclaimed. `unclaimed_path`: only unclaimed. `candidate(dir, name, n)`: `name` or `stem (n).ext`. All of these except `candidate` touch the disk or take a claim callback; call them off async threads.
- `finished_size`: `Some` only for a regular file with no part file, resume file or media work folders beside it.
- `left_by(path, url)`: no file at `path`, a part file, and a resume file whose link equals `url` by a reparse. Does not see a link with a password as equal (05-10).

## Settling (`settle.rs`)

- `Manager::settler` builds the engine's resolver for an unsettled run. It runs on the download's async task and touches the disk (05-9).
- Order on the server's answer: read-as-video check, the expectation check (size, web page), settled name, category (name, then content type), folder (`naming.folder`, else `folder_for`), duplicate check on the first candidate only, then the first candidate that is unclaimed and free or `left_by`.
- On success it saves `row.path`, `row.file_name`, `row.category` and `naming.settled = true`, clears `expect` and `video_check`, and frees the provisional path. It cancels `Run::answered` only on success.
- A run being stopped (`Hold` not free, or `run.stop` set) cannot take a path.
- A later run of a settled download uses `Target::Exact` and never reaches this code.

## File already in the folder (`file_exists.rs`)

- `found_existing` is `None` under the Keep both setting, after a Keep both answer, or when another download claims the path. `Found.same` compares size with the server's total and, when a finished row has that path, the link and size.
- `on_found`: Replace settles at the found path and runs with `ExistingFile::Replace`; Keep existing completes the row with the file's size, no download; Ask sets `Paused` and opens a question with no claim on the found path.
- `Entry::on_existing` is memory only. After a restart a Replace is not honoured (05-6); a Keep both is asked again.
- `answer_file_exists`: removes the question and emits `ConfirmationClosed` before anything else. Errors `ConfirmationNotFound`, `DownloadNotFound` (also when the download is running or being removed), `Closed`. A remembered Replace or Keep both becomes the setting; Cancel is never remembered.
- `close_file_exists` is called by `resume`, `retry`, `cancel` and removal, not by `resume_all`, `refresh_link` or a move (05-7).
- `take_next_free_name`: after the engine's `TargetTaken`, moves the part and resume files to the next free name in the same folder and runs again there; expects `held_for_another_name` first. A failure marks the row `Failed`.

## Moving (`relocate.rs`)

- `set_download_folder`: runs to the end even if the caller stops waiting. It refuses a stranded download, an unfinished media job and a download already held. Same folder is a no-op (05-8).
- `finish_moving` waits for the run to exit, then reads the path. `move_files` proves the folder writable, picks `unique_path`, reserves it for an unfinished download, and moves without ever replacing a file (`rename_no_replace`, else copy to a new file and delete the original; on failure to delete, the copy is removed).
- Unfinished: part and resume files move together, and a failure puts back those already moved. If that fails too, the error is `CoreError::FilesSplit`, the row is `Failed`, `Entry::stranded` is saved and that path stays reserved until retried or removed.
- Copying across drives drops alternate data streams, the Mark of the Web included (05-4).
- An unsettled download moved keeps the folder (`naming.folder`) for the server's answer, and a chosen name becomes the name as it now is in that folder. A `Failed` row moved goes back to `Queued`.
