# Contract 23: interface-commands-and-ui-kit

## `wirecatch_shell::api`

- Plain functions over `&Manager`. Every error is a `ProtocolError` (`CommandResult<T>`) with a code and text ready to show. `refused` gives `InvalidRequest`, `failed` gives `Internal`.
- Most are direct calls of the `Manager` method of the same name; their guarantees are the core's (contract 04).
- `path_text` refuses a path that is not valid Unicode rather than changing it.
- `file_type`: lower case, last extension only. Windows drops trailing dots and spaces first; Linux does not.
- `is_program`: true unless the extension is on `protocol::desktop::SAFE_EXTENSIONS`; also true for no extension and, on Linux, any file marked executable.
- `file_to_open`: only for `Completed`, and the file must exist. Answers `ToOpen::File` or `ToOpen::Program { path, warning }`. The caller must show the warning before opening; nothing enforces that.
- `item_to_reveal`: `Reveal::File` when the file exists, else `Reveal::Folder` when its parent exists, else refused. Both disk checks run on a blocking thread.
- `question(m, id)`: looks through captures, media choices, add-on requests, file-exists questions and media being read, in that order; `None` once closed.
- Not used by anything today: see finding 23-11, and `suffix_list`, `check_suffix_list` (23-5).

## `crate::library::Library`

- One entity. `Library::new` loads; `load` subscribes before it reads, so no event is lost between snapshot and stream. It reloads by itself on `RecvError::Lagged`, and `main_window/empty.rs` calls it after a failed open.
- `downloads` is in the manager's order only at load. Afterwards a changed row keeps its index, a new row goes last, and only `reorder` moves rows (23-1). Windows must not take its order as run order across a queue move.
- `apply` defers `download_windows::follow` to after the update and calls `finished::follow` first, for every event. A missed event is not replayed to them: a reload restores state, not notices.
- `open_questions` is replaced at load and kept from `asked_question` events and `ConfirmationClosed`. Each load also calls `download_windows::restore`.
- Emits `SettingsChanged` at each load and settings event, and `Asked` for `WindowRequested`, `LinksRequested`, `BrowserSettingsRequested`. `Asked::Reveal` is emitted by others.
- `storage_problem` is set by `StorageFailed` and cleared only by the banner's buttons (23-10). `startup_notices` is refilled at each load (23-9).

## `crate::files`

- `choose_folder`: `None` when nothing is picked, the picker failed (23-6) or the name is not valid text (the last tells the window in front).
- `open`, `show_in_folder`: show refusals as a notification in the given window. A program opens only through `ask_to_open`, on the alert's Open button.

## `crate::links`

- `extract`: every link in the text, once each, in order, normalised by `url::Url`. The regex takes http, https, ftp and ftps; the manager still validates. See 23-2 for what is cut.

## `crate::text`

- Pure formatting, except the local clock and one process-wide clock format set by `set_clock` (12-hour until settings arrive; relaxed atomic).
- `per_mille`: 0 to `PER_MILLE_DONE`, `None` only while running with no known total. `Processing` reads the step's own progress.
- `percent`: see 23-3. `status_label` ignores the processing step (23-4); `status_short` does not.
- `host` and `link_for_display` split the text without parsing; they are correct for links the manager normalised. `link_for_display` hides passwords and bare user names, not query strings.

## `crate::theme` and `wirecatch_shell::appearance`

- `init` once after `gpui_kit::init`; `follow` applies on `SettingsChanged`; `follow_system` per window reapplies on a change of system scheme, not on a change of accent alone.
- `apply` sets scheme, native menu scheme, accent overrides and the preferred font. The fixed accents hold 4.5:1; the system accent does not always (23-7).
- `set_menu_scheme` uses undocumented uxtheme ordinals 135 and 136, and returns quietly if absent.

## `crate::ui`

- Screens draw through these: `Role` and `Typed::text_role` for text, `ICON`, `ICON_SMALL`, and `Callout`, `Field`, `FolderRow`, `SwitchRow`, `FileTile`, `QueueTile`, `SelectCircle`, `choice::{one_of, any_of}`, `layout::{body, section, bar, label_row}`, `small_title_bar`.
- All dialogs open through `ui::dialog::{open, open_alert}`. `focus_after_opening` gives the field focus after the dialog takes it.
- `one_of`: pressing the picked option does not call `pick`. `any_of` hands over all pressed indexes.
- `SelectCircle` stops its click from reaching the row.
- `FolderRow` uses fixed element ids, so one per element scope.
- `icon::Assets` serves the named extras, then gpui-kit's set; a test checks every `IconName::` and `Lucide::` written in `crates/desktop/src` is bundled.
- `SpeedHistory`: at most 60 samples, at most one a second; a sample inside the second replaces the last. `speed_graph` and `run_graph` fill the element the caller sized. `thousandths` clamps to 0..=1 and treats a zero whole as one.
