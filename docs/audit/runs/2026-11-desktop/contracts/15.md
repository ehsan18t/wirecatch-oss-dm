# Contract 15: stream-download

How `wirecatch-streams`'s `download`, work folder, decryption and join really behave.

## Entry

`download(StreamRequest, Arc<StreamProgress>, CancellationToken) -> Result<Outcome>`. Order: absolute output, `Fetcher` on a child token `stop`, `Source::load`, `plan`, `NeedsFfmpeg` check, `WorkDir::open`, fetch, join. Nothing is fetched and no folder is made before the plan is accepted.

## Cancelling

- Before the work folder is open (playlist reading): `Err(Error::Cancelled)`. Core maps it to paused. After: `Ok(Outcome::Paused { segments_left })`, 0 during joining.
- A failed segment cancels `stop`, not the caller's token. Errors of workers after `stop` are dropped; the first real error is returned. If the caller's token is also cancelled, the result is `Paused`, whatever failed.
- `Fetcher::save` runs through tokio file calls, outside `request.file_work`; the file steps after it (decrypt, rename, join, remove) run inside it.

## Work folder

`<output name>.wcstream/` beside `output` (core makes `output` itself live in `wirecatch_media::work_dir`, so there are two nested folders):

- `stream.txt`: `wirecatch-stream 2 <fingerprint>`. Any other content, or any read error, clears the folder. Layout 1 with the same fingerprint is kept and rewritten.
- `done.log`: `S track index size`, `A track next size`, `J track size`. Whole lines only count. `S` needs the file at exactly that size, `J` the track file at exactly that size, `A` the track file at least that size. Only `A` lines are synced, which also flushes earlier lines.
- `t<track>/<index:06>.seg`, `.part`, `track<n>`, `joined.<ext>`.
- `.part` is truncated at the start of every fetch: no segment continues mid-way. A plain segment is synced and renamed; a decrypted one is written straight to `.seg` and synced. Its size is checked only against its log line, never its content.
- Reuse depends only on the fingerprint (`Plan::fingerprint`: no hosts, no signing values). A refreshed link with the same paths keeps every segment and joined track, good or bad.

## Join

- Per track: appended in order to `track<n>`, cut back to the last `A` first, synced before its line, segments removed after it, in batches of 64 MiB. `J` follows. Tracks are never rewritten after that, and ffmpeg failures keep them.
- With ffmpeg: every track is passed through `InputFormat::detect` (first bytes of the first segment only). `None` is `Error::UnknownFormat`. Then the first container, then its fallback on `Error::Ffmpeg` only. A stall (`FfmpegRun`) or a missing program returns at once.
- Without ffmpeg: one track only, moved out of the folder. An unknown format is saved as `.ts`.
- `move_to_free_name`: replaces a file only at exactly the requested path. A changed extension takes the first free name.
- The last step deletes the work folder, and a failure there is returned as `Error::Io`, even though the file is already saved.

## Decryption

`crypto::decrypt` streams 256 KiB at a time in caller-kept memory. `None` for a bad length or padding (`Error::Decrypt`); padding is the only check, so a wrong key passes about 1 time in 256. Keys are fetched once per URL per run; a failed fetch is not cached. Keys are exactly 16 bytes, answers over 1024 bytes refused.

## ffmpeg arguments (also used by `wirecatch-media`)

- `preamble`, `progress_args`, `file_argument`, `input_args_for`, `ffmpeg_input_args`, `copy_arguments`. Every path is one absolute `file:` argument; `FileArgumentError` when it cannot be made absolute. Every input: `-protocol_whitelist file -format_whitelist <d> -f <d>`.
- `InputFormat::detect` blocks, reads 512 bytes, skips one ID3v2 tag. It only proves the head: one `0x47` byte counts as MPEG-TS.
- `copy_arguments` maps `v?` of video inputs and `a?` of audio inputs; a video input's own audio only when no input is audio alone. Subtitles and data streams are dropped.
- `ffmpeg::run` is `Ok(true)` on exit 0, without looking at the result; `Ok(false)` when cancelled.

## Progress

`segments_done` and `bytes` start from what was kept. `bytes` counts bytes as received (ciphertext for encrypted segments in this run, plain text for kept ones). Failed segments' bytes stay counted until the next run.
