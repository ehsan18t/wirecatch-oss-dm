# Contract 18: queues-and-scheduling

## `wirecatch-queues`: pure rules

- `plan::plan(queues, downloads, global_max) -> Plan { start, stop }`. Pure. `Stopping` downloads claim slots first, then `Running` by `position`; a `Running` one over its queue's limit, over the app's, in a closed queue or in an unknown queue is stopped. A download being stopped in this pass frees its slot at once (18-4). Waiting ones start in turn across open queues in the order given, `first` before others, then by lower `position`. A running download is never pre-empted by a waiting one ahead of it.
- `schedule::Gate::is_open(schedule, since, now, has_work)`: no schedule is open; with a stop time it is the window, and the gate keeps no memory; without one, it opens when a start in `(since, now]` is crossed (searching at most 7 days back) and closes as soon as `has_work` is false. Work added after a run ended waits for the next start. `Gate::reset`, `Gate::resume_run` set the memory by hand. Not persisted.
- `schedule::allows(schedule, now)`: for display only. Without a stop time it is "from the start until the day ends on a listed day", which can disagree with `Gate` (18-2).
- Windows: half open, start before stop; start after stop runs past midnight and belongs to the day it starts; start equal to stop is that whole day. Empty `days` means every day. Invalid times never open.
- `schedule::next_minute`, `is_valid_time`: helpers; schedules have minute precision.
- `rules::find(queues, link, is_local) -> Matched { matched, switched_off }`: kinds in the order site (most specific; tie: earlier queue), file name, file type (first queue in order, longest extension within that queue), category, protocol. `switched_off` is set only when, counting queues that are off, the winner would be an off queue. Nothing in it moves existing downloads.
- `rules::checked(QueueRules) -> Result<QueueRules, String>`: trims, drops empties and repeats (compared lower case, see 18-5), normalizes file types, limits `MAX_RULES_PER_KIND` and `MAX_RULE_CHARS`, compiles regular expressions with a 1 MiB limit. The `String` is written for the person. `find` skips a stored rule it cannot read.
- Site patterns: `example.com` covers itself and names under it; `*.example.com` only names under it; addresses, CIDR ranges and `10.*` cover IP hosts only; `<local>` asks `is_local`.

## `wirecatch-core`: applying them

- `State::place(request, candidate)`: `Picked` must exist (`QueueNotFound`); else a rule; else for `Browser` the named queue or the extension's default queue, a gone one falling to the default queue; else the default queue. `Placed::answered` turns a differing answer into `Picked`. `Placed::request` answers `App` for all but `Picked`; it is used only for downloads added in the app.
- `Manager::reconcile(state)`: no-op once closed. Updates `last_checked`, evaluates every gate, plans, stops with `Stop::Requeue`, starts, then refreshes `row.waiting` for every unfinished row (rows changed go out on the next tick). Called after almost every state change, and by `run_scheduler` each minute while any queue has a schedule and on `queues_changed`.
- `has_work` counts only running, stopping and `Queued` free rows. A row `Paused`, in a question or under `Hold::Moving` does not hold a run open (18-1).
- `running_outside_schedule` is stored; it ends when the queue has no work or is paused. `paused` is stored.
- `create_queue`, `update_queue`: validate through `wirecatch_settings::validate_queue` (which calls `rules::checked` and checks times), then unique name, then saved proxy. A changed schedule resets the gate; a changed speed limit reaches the limiter at once; connections and proxy apply from the next run.
- `delete_queue`: refused for the default queue; every row moves to the end of the default queue with `QueueReason::DefaultQueue`, running ones stop with `Requeue`; pending captures and media waits follow; the extension's default queue follows; the batch is discarded.
- `set_queue_order`: must name every queue once with the default queue first; saves and publishes, does not reconcile.
- `Manager::run_policy(state, queue)`: connections from the queue or the app, at least 1; limiters global then queue; a gone queue gets the app's policy. `app_policy` has no queue limiter and is for reading before a run.

## `Batches`

- Fed from the ticker only: `observe` for rows that changed, `settle` for queues done, `take_unsaved` to store. `forget` on removal, `forget_queue` on delete.
- A queue is at work while a row is `Queued`, `Connecting`, `Downloading` or `Processing`. `Paused`, `Failed`, `Completed`, `Cancelled` do not hold it. A paused queue with waiting rows stays open.
- A batch reports only if something finished or failed; a row tried again counts by its last end; a finished row moved between queues starts nothing. A stored batch of a queue with nothing at work at start-up is dropped unreported.
- `QueueFinished` is emitted whatever the queue's `notify`; the shell decides whether to tell the person.
