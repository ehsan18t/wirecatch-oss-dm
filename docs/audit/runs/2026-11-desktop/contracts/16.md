# Contract 16: wirecatch-media

Turns what yt-dlp and streams offer into the quality choice, and builds and runs the yt-dlp and ffmpeg commands that make the file. Only `crates/core` (chunk 17) drives it.

## Choice (`choice`)

- `from_stream(info, ffmpeg)` and `from_page(info)` return at most 12 `Offer`s `(MediaOption, Plan)`, best first, audio-only last and never cut. Live pages, DRM-only pages and pages with nothing usable give a worded `UserError`.
- `Plan::resolve(choice, selection)` checks a selection against the offer and gives `Resolved { job, ext, needs_ffmpeg }`. Original with nothing added returns the plan's job unchanged. Errors: `ResolveError` (format, subtitle, too many, audio quality).
- A stream offers only Original; `Plan::variants` is empty for it.
- Extensions are only media extensions (`safe_ext`, `is_media_ext`); a site cannot choose a program's.

## Output (`output`, `convert`, `merge`, `ffmpeg`)

- `output::video_variants` and `audio_variants`: one `Variant` per Save as format, Original first. MKV always copies; other containers copy what fits and re-encode the rest (D24).
- `merge::join` copies video and audio into one file; `convert::convert` follows an `OutputJob`; `convert::to_srt` makes a `.srt`. All three run through `ffmpeg::run`.
- `ffmpeg::run` guarantees: `Finished::Done` only when ffmpeg succeeded and the file exists; any other end removes the partial output, and the inputs stay. Stops after `STALL_TIMEOUT` with no report and no change in the output.
- Every ffmpeg input is a named format from a local `file:` path. Downloaded media is identified by `InputFormat::detect`, subtitles by `SubtitleFormat::detect` and pictures by `ImageFormat::detect`; refusal comes before ffmpeg starts. Site text reaches ffmpeg only through `ffmetadata` (escaped, control characters dropped, 300 characters, 1,000 chapters) and `-metadata` values (one argument each, no shell).
- `EncoderCatalog`, shared through `MediaTools`: lists and probes encoders once per ffmpeg. A failed list is not kept. A hardware encoder is blamed only when a software one then converts the same video. Without a list, only the add-on's software encoder is tried.
- `MediaTools` clones share `is_broken` and the catalog. `describe` marks them broken when an add-on program cannot start; core must look at the add-on again.

## yt-dlp (`ytdlp`)

- `extract` and `download` run with config and plugins ignored, the add-on's Deno and cache, an argument list, `--` before the page, and `Context::proxy` (`Some("")` is no proxy, a URL goes in the environment, `None` lets yt-dlp read the computer's).
- On YouTube the cookies are used only after a failure whose text asks for a sign-in (`SIGN_IN_MARKERS`); on other sites from the first try.
- Cookies: a file in `temp_dir`, owner only, bound to the page's exact host, removed after the run or on drop. Core empties that folder at start for what a crash left.
- `download` works in `work`; `Fetched::Done(path)` is always `media.<ext>` straight inside `work`, links resolved. It may return any extension yt-dlp chose, so the caller decides the final name. A cancelled download is `Fetched::Cancelled`, but a cancelled `extract` is `Err(YtDlpError::Cancelled)`.
- Known fault (16-1): the path in `-o` is read as a template, so a work folder with `%(`, `%%` or a variable sends the file elsewhere.
- `selection` names formats by an exact filter; `FormatId` holds only letters, digits and `_ . - =`.
- `Info` tolerates odd values in most fields; a format that does not read is left out alone.

## Progress and names

- `MediaProgress`: one lock, read as one `Reading`. `start_over` clears everything, including the step and the retry time. `set_own` replaces yt-dlp's last report, and is not a sum across formats (16-3).
- `work_dir(output)` is `<output>.wcmedia`; `stream_dir(output)` is the streams crate's folder.
- `file_name(title, ext)`: at most 150 characters of title, then `sanitize` (200 bytes, safe on both systems), `mkv` for a non-media extension. Known fault (16-2): it keeps only what follows a title's last slash.

## Errors

- `describe` is the only place typed errors become `UserError`, each with its fix: a failed conversion offers `KeepOriginal`, a link that no longer leads to the video `RefreshLink`, a page too long or a stream too large no fix, most others `Retry`.
