## Findings

### 14-1 [P1] A DASH template can ask for an address of hundreds of gigabytes, which aborts the app

- Where: `crates/streams/src/dash/template.rs`, `substitute_into` and `TrackPieces::push`
- Category: bug
- Failure: a manifest of at most 8 MiB holds `<Representation id="(4 MiB of text)">` with `<SegmentTemplate media="$RepresentationID$$RepresentationID$..." duration="1"/>` (about 233,000 repeats in 4 MiB). When that track is planned, the first address needs 233,000 x 4 MiB, about 977 GiB, in one `String`. The process exhausts memory: an allocation failure aborts it, taking every running download with it. A 1 MiB template with a 1 MiB id still asks for about 58 GiB.
- Evidence: `substitute_into` does `out.push_str(id)` for each `$RepresentationID$` with no limit on `out`. The only length check, `MAX_URL_LEN` in `plan::web_address`, runs in `join` after the whole text is built. `MAX_WIDTH` exists for this same reason ("a hostile manifest cannot make one address huge"), but it covers only number widths. `representation` counts the id against `MAX_MANIFEST_NAME_BYTES` (8 MiB), which a 4 MiB id passes, and nothing limits a `media` attribute. Reached from `Source::plan` through `plan_dash` and `Segments::Template(template) => template.expand()`, so on any download of the manifest. `inspect` does not expand templates, and `manifest_memory.rs` measures only `inspect`, so no test reaches this.
- Confidence: certain

### 14-2 [P1] A large HLS master playlist blocks inspection for minutes to hours on a runtime thread

- Where: `crates/streams/src/source.rs`, `Source::auto_picks`; `crates/streams/src/select.rs`, `variant_named` and `paired_audio`; `crates/streams/src/plan.rs`, `MAX_MANIFEST_ENTRIES`
- Category: inefficiency
- Failure: a website serves a master playlist of `#EXT-X-STREAM-INF:\na\n` repeated up to the 8 MiB limit (about 399,000 qualities, 21 bytes each), and any valid media playlist at `a`. `inspect` then does about 8e10 string comparisons in `audio_with.iter().any(..)` and as many again in `variant_named`, minutes of work. With `CODECS="x"` on each line (about 270,000 qualities), every step of `variant_named` also runs `audio_only()`, which allocates in `Codec::list` and lowercases the name: 3.6e10 such calls, about an hour by estimate. With renditions added, `paired_audio` scans every rendition for every quality. The loop is plain synchronous code on a tokio worker, so the `CancellationToken` and any timeout around `inspect` cannot stop it.
- Evidence: `auto_picks` loops over every id in `info.video`, and for each one calls `self.select`, which runs `variant_named` (`(0..variants).find`) and `paired_audio` (a filter over all renditions), and checks `audio_with` by linear search. HLS has no limit like DASH's `MAX_REPRESENTATIONS` (4096), which keeps the same loop harmless there. `MAX_MANIFEST_ENTRIES` (`4 * MAX_SEGMENTS` = 800,000) is meant to be that bound, but the shortest entry takes 21 bytes, so an 8 MiB playlist cannot reach it: `TooManyEntries` never fires for a fetched playlist, only in the unit test that parses a larger string. Its doc also counts pieces, which `MediaReader` does not spend against it. `dash/tests.rs` records the same kind of defect for DASH as a bug ("20,000 took two minutes") and guards it by counting; HLS has no such guard.
- Confidence: certain

### 14-3 [P2] HLS key addresses count against no address budget, so 8 MiB of playlist can hold about 1.5 GiB

- Where: `crates/streams/src/hls.rs`, `update_keys`, `encryption` and `MediaReader::segment`
- Category: inefficiency
- Failure: a media playlist served from an address near `MAX_URL_LEN` (a master's quality line or a redirect can give it) repeats `#EXT-X-KEY:METHOD=AES-128,URI="k"` followed by `http://a/b`. That is 45 bytes per segment, so about 186,000 segments. Each segment keeps its own `Arc<Url>` of about 8 KiB for the key, about 1.5 GiB in total, while `AddressBudget` sees only the 10-byte segment address. A second form: each `#EXT-X-KEY` with a different `KEYFORMAT` stays in `MediaReader::keys`, which `keys.retain` filters on every key line and `usable_key` scans on every segment. About 195,000 such lines hold about 1.5 GiB with no segment at all, and `retain` makes about 2e10 comparisons meanwhile.
- Evidence: only `piece.url` and the map's address go through `self.budget.spend`. The key's `Arc<Url>` is made in `update_keys` by `base.join(u)` with no budget, and `check_web_address` in `encryption` checks only its length. `keys.retain(|k| k.format != format)` removes only keys of the same format, so `keys` grows with each new format. The doc of `MAX_MANIFEST_URL_BYTES` promises a bound on "the most address text one playlist or manifest may resolve to", and media playlists do not use `ManifestBudget` at all. `tests/manifest_memory.rs` serves only DASH manifests, so HLS memory is not measured.
- Confidence: certain

### 14-4 [P2] Automatic audio picks another language when the default audio is inside the video

- Where: `crates/streams/src/select.rs`, `paired_audio`
- Category: wrong implementation
- Failure: a master playlist has `#EXT-X-MEDIA:TYPE=AUDIO,GROUP-ID="a",NAME="English",DEFAULT=YES` with no `URI` (RFC 8216: the audio is in the variant's own stream) and `#EXT-X-MEDIA:TYPE=AUDIO,GROUP-ID="a",NAME="French",URI="fr.m3u8"`. With `Choice::Auto`, French is chosen as a separate track. With ffmpeg, the saved file has only French audio, because the video input then maps `0:v?` alone and the English audio is dropped. Without ffmpeg, the download fails with `Error::NeedsFfmpeg` although the variant could be saved on its own with its default audio.
- Evidence: `paired_audio` filters on `r.url.is_some()` before it looks for `default` or `autoselect`, so the default rendition is never seen when it has no address. Its doc says it takes "the default rendition of its audio group". `ffmpeg.rs` builds `separate_audio = inputs.iter().any(|i| i.role == Role::Audio)` and maps the video input's audio only when that is false. Every multi-rendition test in `crates/streams/tests` gives the default rendition a `URI`.
- Confidence: certain

### 14-5 [P2] A subtitle codec in a variant's CODECS turns an MP4-ready video into MKV and hides an audio-only variant

- Where: `crates/streams/src/codec.rs`, `Codec::list` and `Container::for_copy`; `crates/streams/src/hls.rs`, `Variant::audio_only`
- Category: wrong implementation
- Failure: a variant with `CODECS="avc1.640028,mp4a.40.2,wvtt"` (or `stpp.ttml.im1t`) is saved as `.mkv` although subtitles are never downloaded and both tracks that are downloaded fit MP4, against the D24 and D31 policy of MP4 for H.264 and H.265. A variant with `CODECS="mp4a.40.2,wvtt"` and no resolution is listed as a video quality rather than as audio.
- Evidence: `Codec::from_name` gives `None` for a subtitle format, as its doc says, the same answer as for an unknown media codec. `Container::holds(None)` is true only for Matroska, so `for_copy` falls to Matroska, in the forecast (`StreamInfo::extension`) and in the download (`container_for`, from `Track::codecs`). `Codec::all_audio` requires every entry to be `Some(Audio)`. The test `copy("avc1.64001f,something", false)` covers an unknown name, for which Matroska is the right answer, not a known subtitle format.
- Confidence: certain

### 14-6 [P3] The key error prints the whole signed address to the person and into what is saved

- Where: `crates/streams/src/error.rs`, `Error::Key`; built in `crates/streams/src/download/fetch.rs`
- Category: design
- Failure: an expired or wrong AES-128 key, on a key link with a signing query, gives "The decryption key at https://host/key?token=... is not usable", possibly thousands of characters long. `media::describe` passes `error.to_string()` on as the person's message, with signing tokens in it.
- Evidence: `Error::Key { url }` holds `url.to_string()` and its message prints it. `Error::Manifest`, the sibling error for the same kind of link, keeps only `url.host_str()`. `describe` sends `E::Key` through `with(Some(FixAction::RefreshLink))`, whose message is `error.to_string()`. docs/ENGINEERING.md section 6 treats URLs with signed tokens as secrets, with log redaction as a net and not leave to break the rule.
- Confidence: likely
