## Findings

### 27-1 [P2] The proxy form says a saved password is kept, then saving forgets it

- Where: `crates/desktop/src/main_window/proxy_dialog.rs`, `ProxyForm::new` (password placeholder), `ProxyForm::draft`, `ProxyForm::login_entered`
- Category: wrong implementation
- Failure: edit a saved proxy that has a password, change its server, port, type or user name, and leave the password field empty as its placeholder "Leave empty to keep the saved password" says. Save removes the password with no word. The next download through it fails with a refused login. Test connection in the same state sends no password, and the form then says "The proxy rejected the user name or password", though the person thinks the saved one was tried.
- Evidence: `draft` sends `Update::Keep`. `wirecatch_settings::proxy::merge_password` answers `Update::Keep` with `saved.filter(|_| same_proxy(was, now))`, so any change of type, host, port or user gives `None`, and `update_proxy_server` removes the login. Forgetting is D71.2's deliberate rule, and the module doc repeats it, but the placeholder is fixed when the form opens and nothing in the form changes when those fields do. `login_entered` also still counts the saved password in that state.
- Confidence: certain

### 27-2 [P2] The import preview hides what it does to proxy servers and their passwords

- Where: `crates/desktop/src/main_window/backup_dialog.rs`, `INCLUDED`, `EXCLUDED`, `BackupForm::preview_body`; `crates/protocol/src/app.rs`, `ImportPreview`
- Category: wrong implementation
- Failure: import a file holding a proxy named like a saved one but with another server. The preview, which says "Importing this file makes the changes below", lists folders, queues and add-ons only. Import replaces the server, adds any other proxy in the file, and deletes the saved password of the replaced one. A global proxy in the file becomes the app's proxy with no password, so downloads fail on a refused login with nothing having warned of it. On the export side, the file carries each proxy's host and user name while the dialog's list of what is in the file never mentions proxies, and "Not included" names only site passwords.
- Evidence: `settings_file::export` writes `proxy_servers`; `merge_proxies` adds and updates by shown name; `Manager::import_settings` keeps a login only when `same_proxy` holds. `ImportPreview` has only `folders`, `queues_added`, `queues_updated` and `addons_to_offer`, and `preview_import` drops what proxies would change.
- Confidence: certain

### 27-3 [P2] Enter in the delete queue field closes the question and deletes nothing

- Where: `crates/desktop/src/main_window/queue_delete.rs`, `ask`
- Category: bug
- Failure: in Delete queue, type the queue's name exactly, as the field asks and where the keyboard already is, and press Enter. The dialog closes as if confirmed and the queue stays, with no message. A partly typed name closes it the same way.
- Evidence: `ask` focuses the single-line input and sets no `.on_ok`. The input's Enter handler calls `cx.propagate()` (gpui-base `input/base/state.rs`), so Enter reaches the dialog's `Confirm` binding. gpui-component's `ok_handler` (`dialog/dialog.rs`) defaults to a handler that returns true, which closes the dialog. `link_trial.rs` records this same path in its comment ("a dialog's Confirm would save it"), and the queue and proxy editors install their own `on_ok` for it. The other dialogs with no `on_ok` (`backup_dialog::open`, `proxy_dialog::ask_delete`) close the same way on Enter, which is harmless there because focus is in no field.
- Confidence: likely

### 27-4 [P2] About says the media add-on is not installed while it updates or after a failed update

- Where: `crates/desktop/src/main_window/settings/about.rs`, `addon_versions`
- Category: bug
- Failure: during any add-on update, the quiet automatic one included, or after one fails, About shows "Not installed" while the add-on is installed and works. This is the page the app points to for a problem report.
- Evidence: `addon_versions` shows versions only for `Installed` and `UpdateAvailable`; every other state falls to `Some(_) => "Not installed"`. `Manager::addon_info` gives `Installing` for any running operation and `Failed` for `slot.failure` before it looks at `slot.tools`, and it fills `installed_version` from the record in all of them, so the right value is at hand.
- Confidence: certain

### 27-5 [P2] Saving a queue for any reason changes its speed limit

- Where: `crates/desktop/src/main_window/queue_dialog.rs`, `in_unit`, `speed_limit`, `QueueForm::new`, `QueueForm::set_unit`
- Category: wrong implementation
- Failure: set a queue's limit to 1075 KB/s and save. Reopen it, change only its description and save: the limit is now 1024 KB/s. 1100 KB/s becomes 1126.4 KB/s the same way. Switching the unit also moves the value, against `set_unit`'s doc ("keeping the speed typed"): 300 KB/s to MB/s and back gives 307 KB/s.
- Evidence: `Unit::of` shows anything from 1 MiB up in MB/s, and `in_unit` rounds to one decimal. `read` always sends the field's text back through `speed_limit` while the limit is on, so the rounded text replaces the stored bytes. 1075 KB is 1,100,800 bytes, shown as "1", saved as 1,048,576. The test covers only values exact to a tenth.
- Confidence: certain

### 27-6 [P2] Settings, Media shows an empty Resolution after a less common quality is remembered

- Where: `crates/desktop/src/main_window/settings/media.rs`, `QUALITIES`, `video`; `crates/core/src/manager/media.rs`, `remember_media_choice`
- Category: bug
- Failure: pick a 240p or 144p quality (or any height outside the list, such as 1036p) in a video's window. The core saves `VideoQuality::Height(240)` as the next start, and Settings, Media then shows Resolution as a button with no label and no entry ticked, while "If a video doesn't offer that resolution" shows beneath it.
- Evidence: `QUALITIES` holds only 2160, 1440, 1080, 720, 480 and 360. `remember_media_choice` saves any `option.height`. The `choice` helper in `settings/mod.rs` answers `SharedString::default()` for a value it does not list, and gpui-component's `DropdownField` draws that as its label.
- Confidence: certain

### 27-7 [P3] Check for updates and Copy from system give no answer when there is nothing to do

- Where: `crates/desktop/src/main_window/settings/addon.rs`, `buttons`; `crates/desktop/src/main_window/settings/network.rs`, `servers`
- Category: broken feature
- Failure: with the add-on up to date, Check for updates shows no sign that it ran or what it found. With no proxy set on the computer, or with it already saved, Copy from system does nothing visible, though the empty list's text suggests it. The app's own update check, by contrast, says "You have the newest version."
- Evidence: both go through `command`, which reports only errors, and both discard the result with `.map(|_| ())`. `check_addon_updates` returns `Ok` and only emits an unchanged `AddonsChanged`. `copy_system_proxy` answers `Ok` with no ids added and emits nothing. Neither button has a busy state.
- Confidence: certain

### 27-8 [P3] The queue editor's proxy list moves its cursor back ten times a second while downloads run

- Where: `crates/desktop/src/main_window/queue_proxy.rs`, `ProxyForm::new` (`listing`)
- Category: bug
- Failure: open the queue editor while anything downloads, open the Proxy list and press the arrow keys, or scroll it. The cursor returns to the selected entry at each progress tick, so with many saved proxies the list cannot be navigated by keyboard. The list of names is also rebuilt each time.
- Evidence: `listing` observes the whole `Library`, and `Library::apply` calls `cx.notify()` for each `DownloadsChanged` (at most every 100 ms, contract 04). It then calls `set_items` and `set_selected_value`. In gpui-component, `set_selected_value` clears the query and calls `_set_selected_index`, which sets the cursor and scrolls to it. Only a change of proxies or of the global proxy needs this.
- Confidence: likely

### 27-9 [P3] An impossible port is saved as the usual port without a word

- Where: `crates/desktop/src/main_window/proxy_dialog.rs`, `ProxyForm::settings`
- Category: wrong implementation
- Failure: clear the Port field and Save, or type 70000 and press Enter, which saves without a blur to clamp it. The proxy is saved on 8080 (1080 for SOCKS5) with no message, and the connection test runs on that port too.
- Evidence: `settings` reads the port with `.parse().unwrap_or_else(|_| usual_port(self.kind))`. `check_server` has its own message for a missing port ("Enter the port of the proxy server"), but only port 0 reaches it. The queue editor's number fields refuse the same input through `whole`.
- Confidence: certain

## Suggestions

### 27-S1 Test a saved proxy with a visible state

- Today: the Test button on a saved proxy's row shows nothing until the row's last test changes, which takes up to the test's whole time limit when the proxy does not answer.
- Better: show it as testing, as the proxy editor's own Test connection does.
- Value: the person knows the click took effect and does not press it again.

### 27-S2 Let a type's folder go back to the download folder

- Today: Folders by file type has Change only. Once a type has its own folder, the app offers no way back to following the download folder, and a rule made by typing extensions copies the current folder rather than following it.
- Better: a Reset beside Change, as the queue editor's folder row has for its own folder.
- Value: moving the download folder later does not leave types behind.
