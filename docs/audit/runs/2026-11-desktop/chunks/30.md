## Findings

### 30-1 [P2] The file-exists question never says whether the file is the same one

- Where: `crates/protocol/src/app.rs`, `FileExistsQuestion` (`same_file`, `size`, `saved_at`); `crates/desktop/src/download_windows/view.rs`, `DownloadWindow::file_exists`
- Category: broken feature
- Failure: a download is asked about a file of the same name that is a different file (another size or link). The window says "A file with this name is already in {folder}", the same words as for an identical file, and offers Replace as its primary button. The person cannot tell that Replace overwrites a different file.
- Evidence: D96 says "The person always knows which case it is: the question says either that the file in the folder looks like the same file ... or that a different file has the same name". `crates/core/src/manager/file_exists.rs` fills `same_file`, and `view.rs` reads only `id`, `file_name`, `url` and `folder`. No product code outside core and the generated types names `same_file`; `question.size` and `question.saved_at` are not shown either.
- Confidence: certain

### 30-2 [P2] Download windows offer only Try again and ignore a failure's fix

- Where: `crates/desktop/src/download_windows/view.rs`, the `Failed | Cancelled` arm of the progress buttons; `crates/desktop/src/download_windows/finished.rs`, `row_buttons`; `crates/protocol/src/desktop.rs`, `Reveal::details` and `Reveal.details`; `crates/protocol/src/app.rs`, `RETRY_FIXES`
- Category: broken feature
- Failure: a download fails while its progress window is open, with a refused proxy login (fix `ChangeQueue`), an FTP link through a proxy (`ProxySettings`), an expired link (`RefreshLink`), a bad folder (`ChooseFolder`) or a failed conversion (`KeepOriginal`). The window shows the message and only Close and Try again, which runs into the same failure. The download complete window does the same for every failed row.
- Evidence: D73.14 says Change queue "from a progress window brings the main window up on" the download's details, and the doc of `Reveal` and `Reveal::details` says the same. `Reveal::details` has no caller, nothing reads `Reveal.details` (`MainWindow::reveal` ignores it), and `crates/desktop/src/download_windows` never names `FixAction` or `.fix`. `RETRY_FIXES` says "a notification and the download complete window offer Try again for them" and the others "need the person's answer first", but only `crates/shell/src/notifications.rs` reads it; `row_buttons` takes no error at all. The fixes run only from the main window (`main_window/fixes.rs`), so the person must find the row there.
- Confidence: certain

## Suggestions

### 30-S1 Stop generating into TypeScript what only Rust reads

- Today: `crates/protocol` exports constants such as `DOWNLOAD_WINDOW_*`, `MAX_QUESTION_WINDOWS`, `MAX_FINISHED_*`, `SAFE_EXTENSIONS` and `RETRY_FIXES`, and `#[ts(export)]` on `Reveal` and `FinishedList`, for the Svelte desktop that is gone. They now pass between crates of one process.
- Better: make them plain Rust constants, in `crates/shell` where only it reads them, and keep generation for what the extension reads.
- Value: smaller generated package and validators, and a protocol crate that holds what crosses a process boundary, as ENGINEERING section 1 says.

### 30-S2 Check saved subtitle languages against the codes sites really use

- Today: `same_language` compares codes literally, and `LANGUAGES` offers ISO 639-1 `he` and `tl`. From memory, not checked here, YouTube through yt-dlp has listed Hebrew as `iw` and Filipino as `fil`, which would never match, so the saved language would not be preselected.
- Better: test against real yt-dlp output, and if confirmed, treat the known aliases as one language.
- Value: a saved language is ticked for every video that has it.
