## Findings

### 33-1 [P2] `scripts/linux-test.sh` can never pass: it removes `.git`, and the gate's Rust group needs it

- Where: `scripts/linux-test.sh` (the `tar --exclude=./.git`), against `filesMatching` in `scripts/gate/process.mjs`, reached from `rustLintAttributes` (`cfg-allow`) and `testTiming` (`test-timing`)
- Category: broken feature
- Failure: run `bash scripts/linux-test.sh` as `CONTRIBUTING.md` says. The source reaches the container without `.git`, then `node scripts/gate.mjs --no-desktop --no-fail-fast rust` runs `fmt`, `lint-policy`, then `cfg-allow`. That calls `git grep`, which stops with "not a git repository" and status 128. `capture` allows only 0 and 1, so the gate fails there. `clippy` and every test, the purpose of the script, never run.
- Evidence: `git grep -l --untracked -I -P x -- '*.rs'` in an empty folder outside a repository printed that error with status 128 (this machine). `rust-lint` lists `cfg-allow` third in `scripts/gate.mjs`. Both checks moved onto git grep without the script changing. The container run itself was not done.
- Confidence: certain

### 33-2 [P2] The `test-timing` check does not see `recv_timeout`, so a short wait that has to succeed passes the gate

- Where: `FIXED_WAIT` and `shortWaits` in `scripts/gate/test-timing.mjs`; a live case in `crates/engine/tests/options.rs` (`finished.recv_timeout(DEADLINE)`, the helper that runs a future on its own thread)
- Category: wrong implementation
- Failure: both wait patterns start `\btimeout`, and no word boundary falls between `_` and `t`, so `recv_timeout(Duration::from_secs(1))` and `recv_timeout(SHORT)` are never read. `options.rs` waits at most `DEADLINE`, 10 seconds, for a download that must finish, and fails the test otherwise: the race section 7 of `docs/ENGINEERING.md` forbids, on a slow CI runner. `clippy.toml` itself points people at `recv_timeout` when it refuses a sleep.
- Evidence: `node scripts/gate.mjs test-timing` passes with that line in the tree. `DEADLINE` is `Duration::from_secs(10)`, below the check's `PATIENCE_SECONDS`. The `\btimeout` boundary has to stay for configured limits such as `with_capture_timeout`, which a test case keeps out, so `recv_timeout` needs naming. A related gap with no live case: `upperBounds` matches `took < MOST` but not `took.as_millis() < 500`, since the method call sits between the name and the `<`.
- Confidence: certain

### 33-3 [P3] The product tests are pinned to today's values of `config/product.toml`, so a version bump or filling in the identity fails them

- Where: `scripts/product/read.test.mjs` and `scripts/gate/product.test.mjs`
- Category: design
- Failure: change `version` to `0.2.0`, or give the publisher, website, contacts or updater key their real values, as a release requires. `js-test` then fails with no fault in the code. `changed('version = "0.1.0"', ..)` and the two `changed` calls on placeholder lines assert the text is in the file. `the values still to decide are found as placeholders` compares with the exact five names. `the release check finds every placeholder` asserts five values and a placeholder line in `SECURITY.md`. `a Cargo.lock that still records another version` replaces `version = "0.1.0"`, which then matches nothing, so nothing goes stale and its assertion fails.
- Evidence: each test reads the live file (`PRODUCT_TOML`, or the copy in `root`). None builds its own fixture. Each release therefore has to edit these tests too, and the placeholder cases lose their input for good once the values are decided.
- Confidence: certain
