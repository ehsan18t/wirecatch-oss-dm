## Findings

### 19-1 [P2] The import preview says nothing of proxies or sites on the network, which a settings file can change

- Where: `crates/protocol/src/app.rs` `ImportPreview` and `ImportSummary`, `crates/core/src/manager/preferences.rs` `preview_import`, `crates/desktop/src/main_window/backup_dialog.rs`
- Category: wrong implementation
- Failure: a settings file from someone else holds a proxy profile `attacker.example:8080` with `settings.proxy.proxy` naming it, and `settings.local_sites` holding `attacker.example`. The preview dialog lists folders, queues and add-ons only, so the person confirms without seeing any of it. After the import every queue that follows the app, the add-on and suffix-list fetches and the updater go through that proxy, which sees every host and can change anything fetched over plain HTTP, and pages on `attacker.example` count as on the person's own network, which lifts the local-network guard (D34, D39) for the links they give. An imported profile of the same name also replaces a saved one, and its saved password is forgotten, again without a word.
- Evidence: `ImportPreview` has only `folders`, `queues_added`, `queues_updated` and `addons_to_offer`; `merge_localized` computes `Imported.proxies` and `preview_import` drops them. `backup_dialog.rs` has no mention of a proxy. `import_settings` then starts a background test of every new or changed profile, so the file's server is contacted at once. The same module treats the file as hostile for folders ("A settings file may come from anywhere", `localize_folders`, `PathError::Protected`, `PathError::Network`), and `preview_import`'s doc says the UI "shows this and asks before importing". No decision records leaving proxies out of the preview.
- Confidence: certain

### 19-2 [P2] An import can leave two queues with the same name, and then neither can be edited without renaming it

- Where: `crates/settings/src/settings_file.rs` `merge_localized`
- Category: bug
- Failure: this machine has the default queue "Main" and a queue "Videos". The file's default queue is named "Videos" (renamed on the other machine). The import matches the file's default to this default whatever its name and renames it to "Videos", and the local "Videos" stays. The sidebar, tray and auto-queue lines now show two queues of one name, and any later save of either one (a speed limit, a schedule) is refused with "A queue named "Videos" already exists" until it is renamed. The preview reports only "Changes queues: Main".
- Evidence: `merge_localized` finds the target with `q.is_default == incoming.is_default && (incoming.is_default || name matches)` and never compares the new name with the other queues. `create_queue` and `update_queue` enforce the rule with `ensure_name_free`, which `update_queue` applies with `Some(id)`, so each duplicate blocks the other (`crates/core/src/manager/queues.rs`, `State::queue_name_taken`). `merge_proxies` does this check for proxies (`validate_settings_file(settings, &others)`); the queue side has no counterpart. No test covers it.
- Confidence: certain

### 19-3 [P2] A proxy exception that can never match is accepted and saved without a word

- Where: `crates/settings/src/proxy.rs` `clean_hosts`
- Category: wrong implementation
- Failure: the person pastes `https://intranet.example/`, `intranet.example:8443` or `Bücher.example` into Hosts that skip the proxy. It is saved, and every download from that host still goes through the proxy, which either fails (the proxy cannot reach an intranet) or sends the host through a server the person meant to avoid. Nothing says the entry is useless.
- Evidence: `clean_hosts` refuses only whitespace, control characters, `,`, `;` and length, then lower-cases ASCII. The engine's reader says "any other pattern stays as it is and matches nothing, so its hosts keep the proxy" (`crates/engine/src/proxy.rs` `exceptions`). The error text in `clean_hosts` names the forms it means, but never checks them. D73.8 gives the same grammar as a queue's site claims (D72.10), and D72.13 says a claim it cannot read "is reported, not left unmatched": `rules::checked` does this with `SitePattern::read`, which also turns a web address into its host through `read_site`. Ignored sites (`read_site`) and local sites (`local_site`) are also read on saving; this is the one list of sites that is not.
- Confidence: certain

### 19-4 [P2] yt-dlp goes through the proxy for a host on the exceptions, while the download says it used no proxy

- Where: `crates/settings/src/proxy.rs` `ytdlp_proxy`, its callers `crates/core/src/manager/media.rs` and `crates/core/src/manager/media_run/page.rs`, label from `State::proxy_route`
- Category: wrong implementation
- Failure: a queue uses a proxy profile and lists `videos.intranet.example` as an exception. A media download from `https://videos.intranet.example/watch` runs yt-dlp with the profile's proxy, so the page is read through the proxy and fails if the proxy cannot reach it, or tells the proxy the host. The row's label reads "No proxy (an exception)", from `proxy_route`, which does follow the exceptions.
- Evidence: `ytdlp_proxy` takes only the `ProxyChoice` and returns `https`, `all` or `http` whatever `manual.exceptions` says; neither caller passes the page's host. Its doc states the limit ("has no exceptions"), but D73.6 says "A host on a list in use never goes through a proxy" with no exception for media, and D71.3 says the setting covers yt-dlp. The engine already answers the question: `ProxyChoice::route(&url)` returns `ProxyRoute::Excepted`, and `Some("")` is the form for no proxy. The same gap applies to `ProxyUse::System` with hosts added, since that also arrives as `ProxyChoice::Manual`.
- Confidence: certain

### 19-5 [P2] The limit on proxy exceptions is checked after a quadratic scan, under the manager's lock

- Where: `crates/settings/src/proxy.rs` `clean_hosts`, reached from `crates/settings/src/settings_file.rs` `merge_localized` through `validate` and `validate_queue_exceptions`
- Category: inefficiency
- Failure: a settings file up to the 1 MB limit holds about 150,000 short unique hosts in `settings.proxy.exceptions.hosts`. `cleaned.contains(&entry)` runs for every entry, about 10^10 string comparisons, before the file is refused for exceeding 256 hosts. By estimate (not measured) that is tens of seconds with the manager's lock held, once for the preview and once for the import if it got that far, during which every window and running download's bookkeeping waits on the lock.
- Evidence: `MAX_PROXY_EXCEPTIONS` is compared with `cleaned.len()` only after the loop. `merge_localized` runs inside `lock_open()` in both `preview_import` and `import_settings`. The rule it breaks is stated in `crates/settings/src/lib.rs`: limits "keep validation (done under the manager's lock) ... small, whatever a client or a profile file sends", and `clean_list` checks the count first and uses a `HashSet` ("Linear in the length of the list").
- Confidence: likely (the code path is certain; the time is an estimate)

### 19-6 [P3] Exporting settings over an earlier file is not written whole

- Where: `crates/core/src/manager/preferences.rs` `export_settings`
- Category: wrong implementation
- Failure: the person exports over last month's backup, and the disk fills or the machine loses power during the write. The old file is already truncated and the new one incomplete, so neither can be imported.
- Evidence: it calls `std::fs::write`. `wirecatch_files::whole_file::replace` exists for this ("leaves the old one or the new one, never a part of either") and is used for the add-on record and the suffix list.
- Confidence: certain

### 19-7 [P3] A proxy test cancelled by quitting is saved as that proxy's last result

- Where: `crates/core/src/proxy.rs` `test_one`, `crates/core/src/manager/proxy.rs` `test_in_background`, `keep_test`
- Category: bug
- Failure: the person saves or edits a profile and quits during its background test (up to 20 seconds). `Error::Cancelled` falls into the `other` arm and becomes `Unreachable { reason: "cancelled before the download started" }`. `keep_test` stores it, and after the restart the profile shows a failed test with that reason until it is tested again.
- Evidence: `run_test` passes `self.inner.stopped.child_token()`, which `shutdown` cancels before it waits for the runs and closes the store. `test_one` has no arm for `EngineError::Cancelled`, `keep_test` uses `lock()` with no check of `closed`, and `test_in_background` drops its `JoinHandle`, so nothing stops it from saving through `proxy_servers_changed` before `store.close`. Whether the save lands depends on that race.
- Confidence: likely

### 19-8 [P3] The Test connection's handling of several proxies and of no proxy is never reached

- Where: `crates/core/src/proxy.rs` `test`, and its test `the_test_goes_through_every_proxy_set_whatever_the_exceptions`

- Failure: `test` handles a non-manual choice, walks `all`, `http`, `https` and `ftp`, removes duplicates and drops exceptions. Its only production caller, `Manager::run_test`, always passes a `ManualProxies` with `all` alone and no exceptions, since D73 replaced the per-protocol form with profiles. About 20 lines and one test keep a path alive that no button can start, and its doc describes a setting that no longer exists.
- Evidence: a search for callers finds `crate::proxy::test` only in `crates/core/src/manager/proxy.rs` `run_test`, apart from this file's tests.
- Confidence: certain

### 19-9 [P3] A test named for keeping the result as the last test does not check it

- Where: `crates/core/tests/manager/proxy.rs` `a_test_uses_the_draft_and_the_saved_password_and_is_kept_when_saved`
- Category: fake test
- Failure: deleting the `keep_test` call from `Manager::test_proxy_server` leaves this test passing. Its last step, under the comment "its result is kept as its last test", asserts only the returned result; `last_test` was already set by the earlier background test and is not read again. The branch's conditions (`draft.password.is_keep()`, draft equal to the saved profile) are covered nowhere in this chunk's tests.
- Evidence: the test's last assertion compares the return of `test_proxy_server` with `Works`, and `last_test` is read only before that call.
- Confidence: certain

### 19-10 [P3] `Manager::update_settings` has no caller outside tests, and repeats `change_settings`

- Where: `crates/core/src/manager/preferences.rs` `update_settings`
- Category: dead code
- Failure: the product changes settings only through `change_settings` and `update_extension_settings`. `update_settings` is called only from tests and the `crates/e2e` harness, yet it is public API with its own doc, and it is a third copy of the steps check, validate and apply. A new check added to `change_settings` would not reach what most tests exercise.
- Evidence: a search for `.update_settings(` in `crates/desktop`, `crates/shell`, `crates/server`, `crates/cli` and `crates/bridge` finds nothing; in `crates/core/src` it is only in `#[cfg(test)]` modules.
- Confidence: certain
