## New findings

### B11-1 [P2] A redirect to an address written in raw UTF-8 fails the download

- Where: `crates/engine/src/http.rs`, `send`
- Category: bug
- Failure: a server answers `302` with `Location: /café.zip` in raw UTF-8 bytes, which servers do send. The download fails with `InvalidUrl`, "redirects to ... which is not an http or https address", and the person reads "This link is not a valid web address". Browsers follow it.
- Evidence: `location.to_str().ok()` is `None` for any byte above 126, the same cause as 02-2. `send` follows redirects itself, and every request goes through it, `Fetcher` included. `proofs/B11-1.patch` failed with `Err(InvalidUrl("http://127.0.0.1:61381/start redirects to \"/caf\\xc3\\xa9.zip\", which is not an http or https address"))`.
- Confidence: certain

### B11-2 [P2] Path parameters of a web link end up in the saved file's name

- Where: `crates/engine/src/naming.rs`, `from_url`; callers `crates/engine/src/target.rs` `suggested_name` and `crates/core/src/naming.rs` `file_name` and `settled_name`
- Category: bug
- Failure: `http://host/a.zip;jsessionid=ABC123`, the form Java servlet sites use, with no `Content-Disposition`, is saved as `a.zip;jsessionid=ABC123`. The extension is lost, so the file does not open by double click and category rules see the wrong type. This is 21-2's cause on the web side.
- Evidence: `from_url` returns the whole last segment and `clean` keeps `;`. `proofs/B11-2.patch` failed with left `"a.zip;jsessionid=ABC123"`, right `"a.zip"`.
- Confidence: certain for the name; how often such links carry no `Content-Disposition` is outside the code

### B11-3 [P2] Add-on installs and app updates are told to choose another folder they cannot choose

- Where: `crates/messages/src/lib.rs`, `disk_failure`; callers `crates/core/src/manager/addons/install.rs` and `crates/core/src/manager/app_update.rs`
- Category: wrong implementation
- Failure: the work folder of an add-on install or the update's folder cannot be written. The person reads "yt-dlp could not be downloaded: Wirecatch is not allowed to save files in <app's own folder>. Choose another folder.", or "The folder ... cannot be used. Choose another folder." Those flows have no folder choice, and the fix is dropped.
- Evidence: the same callers as 28-3 pass their private folder as `folder` and keep only `.message`. 28-3 lists the link words only. Read from the code, no test run.
- Confidence: certain
