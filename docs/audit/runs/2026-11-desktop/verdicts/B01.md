# Verdicts: B01 Path claims, file-exists questions and captures

Validated at commit 02284bbd0. Every proof below was run under the batch's own cargo profile, on Windows, in a debug-style build. Linux was not run.

## Verdicts

### G01

- 05-1: confirmed, P0. `replace_at` inserts into `Claimed` without looking, and an open question holds no claim on `Asked::path`. Proven by `proofs/05-1.patch`, which waits for events instead of sleeping: both rows hold `report.pdf`, the first row ends `Completed` with none of its own bytes in the file (`aa 0 bb 4194304`), and the second ends `Failed` with a misleading folder error. P0 stands because a row reports a finished file that is not its download, silently in a release build. It needs two same-named links, a file already there, and Replace on both.
- Xconcurrency-1: confirmed, P0, same bug as 05-1. `proofs/Xconcurrency-1.patch` reran with the output it records. Its "a mix of both is possible" was not reproduced: with the first run's resume file present and files of the same size and no validators, the file still held only the second link's bytes. Mixed bytes stay unproven; the wrong-content result does not depend on them.
- 05-13: confirmed, P3. `remove_entry` and `finish_move` both remove a path a finished row never claimed. In a release build, sharing needs B still queued with Replace and a new download of that name, because once B has a part file the disk check protects it. Not run.
- Xconcurrency-9: confirmed, P3, same bug as 05-13 by the rename window. The window is very short and three downloads are needed. Not run.
- Xconcurrency-10: confirmed, P3. `finish_removing` calls `remove_entry` under the lock and `delete_files` after it, with no `cleanup` token; `unclaimed_path` does not look at the disk. A retry recovers. Not run.

## New findings

### B01-1 [P3] The ` (1)` of a provisional name follows the download into a folder where the name is free

- Where: `crates/core/src/naming.rs`, `settled_name`; `crates/core/src/manager/settle.rs`, `settle_path_checking`
- Category: bug
- Failure: a link `.../stream` with no extension, and a file `stream` in the guessed folder for `Other`. The provisional name is `stream (1)`. The server's `audio/mpeg` places it in Music, which has no `stream`, and the file is saved there as `stream (1)`.
- Evidence: same cause as G02. `settled_name` returns the provisional name when the server names nothing new, and `dir` is worked out afterwards from the category.
- Confidence: likely; traced in code, not run

### B01-2 [P3] Moving a download before the server answers hides the duplicate check the same way

- Where: `crates/core/src/manager/relocate.rs`, `move_files` and `finish_move`
- Category: bug
- Failure: an unsettled download is moved to a folder that holds a file of its name. `move_files` picks `report (1).pdf` with `unique_path`, and the row and any typed `naming.name` take that name. When the server answers, the setting is never consulted, so D96 is skipped.
- Evidence: same cause as G02, and a fix in `insert` alone leaves it. `finish_move` writes `new_name` into `naming.name` for an unsettled download. The doc comment of `set_download_folder` promises the ` (1)`, so this may need a decision rather than only a code change.
- Confidence: likely; traced in code, not run

### B01-3 [P3] Two finished rows on one path: moving or deleting through one leaves the other pointing at nothing

- Where: `crates/core/src/manager/relocate.rs`, `finish_move`; `crates/core/src/manager/downloads.rs`, `finish_removing`
- Category: design
- Failure: Keep existing or Replace leaves two Completed rows on one path. Moving one renames the file and updates only that row. Removing one with `RemoveFiles::Delete` deletes the file the other row still lists.
- Evidence: same cause as G01, for finished files: nothing records who holds a path. `keep_existing` and `replace_at` set `row.path` to a path another finished row may hold, and `found_existing` already looks for such a row, so the state is expected. Only the row acted on is updated.
- Confidence: likely; traced in code, not run
