# Batch B15 verdicts: proxies and secrets in links

Judged from the code and the sources of `hyper-util` 0.1.21, `reqwest` 0.13.5 and `gpui-base` 0.8.1, the versions in `Cargo.lock`. No finding reached P1, so no proof was built. One cost was measured outside the repo (19-5).

## Verdicts

### G73 Proxy exceptions

- 09-3: confirmed, P2. `exceptions` passes `[fd00::5]` on as it is. `NoProxy::from_string` cannot parse it as a network or an address, so it lands in `domains`; `NoProxy::contains` strips the host's brackets, parses an address and looks only in `ips`. The Windows bypass list reaches `exceptions` without `clean_hosts`, so the fix belongs in the engine's `exceptions`, not in the settings check.
- 19-3: confirmed, P2. `clean_hosts` refuses only whitespace, control characters, `,`, `;` and length. `https://intranet.example/` and `intranet.example:8443` become domain entries no `host_str()` can equal, and `bücher.example` never equals the URL's punycode host. The desktop's list fields (`settings/network.rs`, `queue_proxy.rs`) send the lines as typed, so nothing earlier catches them. D73.8 gives a grammar and D72.13 says what cannot be read is reported.
- 19-4: confirmed, P2. `ytdlp_proxy` reads only the proxies, and `media.rs` `read_page` and `media_run/page.rs` both pass the choice without the page. `proxy_route` in `run.rs` uses `ProxyChoice::route`, so the label says "No proxy (an exception)". The doc's "has no exceptions" is a comment, not a decision; D73.6 has no exception for media, and `Some("")` already gives yt-dlp no proxy, so the limit is not yt-dlp's.
- 19-5: confirmed, P2. The count check follows the loop, and `merge_localized` and so `validate` and `validate_queue` run inside `lock_open()` in both `import_settings` and `preview_import`. Measured with the same loop, `rustc -O`, on 150,000 unique six-character hosts, about 1 MB as JSON: 76 seconds. Only a hand-made file reaches it, since `crates/server` offers no settings call and the windows send short lists, but `merge_localized`'s own comment says a huge file costs nothing. A refused preview normally stops the second run, so the "twice" in the finding is rare.

### G74 Proxy forms, tests and leftovers

- 09-2: confirmed, P2. `adopt` writes `socks4://`. reqwest's `connect_socks` picks `DnsResolve::Local`, takes `.next()` from the resolver and writes a bracketed address into the destination. `SocksV4::call` strips the brackets, so `SocksConfig::execute` parses `IpAddr::V6` and returns `SocksV4Error::IpV6`; there is no fallback to another address. Getting IPv6 first depends on the machine and was not run. `ManualProxies::from_system` also carries the value into `ProxyChoice::Manual` when hosts are added to the System proxy, so that path fails the same way.
- 09-7: confirmed, P3. The test sets no proxy and checks only the size. `direct_and_manual_read_neither_the_environment_nor_the_system` in `crates/engine/src/proxy/tests.rs` is the real proof.
- 19-7: confirmed, P3. `Fetcher` returns `Error::Cancelled`, whose text is "cancelled before the download started", and `test_one` turns it into `Unreachable`. `keep_test` uses `lock()` with no check of `closed` and saves through `proxy_servers_changed`. `shutdown` cancels `stopped` and goes on to `store.close`, with nothing waiting for the dropped `JoinHandle`, so the save may land. A race, as the finding says.
- 19-8: confirmed, P3. `run_test` is the only production caller and always passes `ManualProxies` with `all` alone. The non-manual branch, the walk over the other fields and the removal of duplicates are unreachable, and `the_test_goes_through_every_proxy_set_whatever_the_exceptions` is all that keeps them. The doc still describes D71.5's form, which D73 replaced.
- 19-9: confirmed, P3. The test's last assertion reads only the return of `test_proxy_server`. `last_test` is read earlier, after the background test, and no other test in `crates/core/tests` reads it after a `test_proxy_server` call, so removing that `keep_test` call leaves every test passing.
- 27-1: confirmed, P2. The placeholder is fixed in `ProxyForm::new`. `draft` sends `Update::Keep`, `merge_password` answers `None` when `same_proxy` is false, and `update_proxy_server` removes the login with no message; `test_proxy_server` also tests with no password. `login_entered` still counts the saved password. D71.2's rule is deliberate and stays: the fault is that the form promises the opposite.
- 27-9: confirmed, P3, and wider than written. The port's `InputState` sets `min` and `max` but no `MaskPattern::Number`, and `clamp_number_value` returns at once without that mask, so a blur never clamps. `70000`, `80a` and an empty field all become the usual port by any route to Save, not only Enter. `queue_dialog.rs` `whole` refuses the same input.
- Xrepeated-logic-7: confirmed, P3. A search of `crates` finds `updater_proxy` and `UpdaterProxy` only in `settings/src/proxy.rs`, its tests, `core/src/manager/proxy.rs` and the re-export in `core/src/lib.rs`. `Manager::updater_proxy` has no caller.

### G75 Secrets in links

- 05-5: confirmed, P2. `ask` clones `entry.row.url`, the real link, while `FileExistsQuestion::url` documents "with any password removed". The desktop draws only `text::host` of it, so the password never shows on screen, but `crates/server` `serve_connection` sends every event to each client and `crates/bridge/src/relay.rs` passes every frame to the extension byte for byte. The password therefore leaves the app's process and reaches the browser extension, which is what makes it P2.
- 05-10: confirmed, P2. `settle_path` passes `entry.row.url` to `left_by`, and `normalized_url` only reparses, while `download.rs` saves `without_password(&request.url)`. After a stop in the window between settling and the store's save, `naming.settled` is false and the first candidate fails `free_on_disk`, so the run takes `a (1).zip` and nothing owns the old part and resume files. Not raised to P1: only links with a password are affected, the window ends at the store's save, and the download still completes under the new name. `same_download` in `target.rs` has the other direction, so it could not be reused as it is either.
- 20-1: confirmed, P2. Traced both samples: `hide_queries` splits at `'`, and the second word has neither `://` nor a leading `/`; `hide_link_credentials` ends the link at `'`, so the `@` fails `.filter(|at| *at < end)`. `redaction.json` has no apostrophe inside a link. The password in a row also goes out through `Entry::summary` to the bridge. On the desktop's list and details `link_for_display` happens to hide it (see Xrepeated-logic-8).
- 20-2: confirmed, P3. All four samples trace as written: `is_name_byte` takes `.` and `-`, `segments` finds `key`, `auth`, `session` or `cookies`, `kind_of` gives `Kind::Value`, and `field_end(.., false)` runs to the end of the line. `secrets.rs` accepts `Invalid key: 5` losing its value, which is a bare name; D40.10 says the log keeps hosts and paths, and these lose exactly those.
- Xrepeated-logic-8: confirmed, P3, with one correction. Every row leaving the manager goes through `Entry::summary` (`ticker.rs`, `downloads.rs`, `captures.rs`, `media.rs`), so the "likely" in the finding holds. The function is a no-op except where `url_for_display` misses a password: for `https://ada:pa'ss@example.com/f` it does mask, since it reads the host part up to the first `/`. It is still a second copy of one rule.

## Group notes

- **G73 does not share one cause; split it.** 09-3 and 19-3 share one: entries are not read into the matcher's grammar when accepted. 09-3 also arrives from the system's list, which skips `clean_hosts`. 19-4 is a separate cause: yt-dlp's proxy is not chosen by route (see B15-1). 19-5 is only the order of a check, though it sits in the function 19-3 changes, so the two can be one change.
- **G74 has no shared cause, as `GROUPS.md` says.** 19-8 and Xrepeated-logic-7 are both leftovers of D73 replacing D71's manual form and could go together. 19-9 should come after 19-8 only if the same test file is reshaped; they are otherwise separate, as are 09-2, 09-7, 19-7, 27-1 and 27-9.
- **G75 does not share one cause; split it.** 05-5, 05-10 and Xrepeated-logic-8 do share "the real link and the shown link are told apart at each use". 20-1 and 20-2 are two separate faults in the redaction's scanners, opposite in direction (too little hidden, too much hidden), in different functions.
- **Order inside G75:** fix 20-1 before removing `link_for_display`. Removed first, a password with an apostrophe would appear on the desktop's list and details.

## New findings

### B15-1 [P3] yt-dlp takes the HTTP proxy for an HTTPS page that the engine reaches directly

- Where: `crates/settings/src/proxy.rs`, `ytdlp_proxy`
- Category: wrong implementation
- Failure: the system's proxy is per protocol with only `http=proxy:80`, and hosts are added to the System proxy, so it arrives as `ProxyChoice::Manual` with `http` alone. For `https://videos.example/watch` the engine goes directly and the row says "No proxy", while yt-dlp is given `http://proxy:80`.
- Evidence: `.https.or_else(all).or_else(http)` has no check of the page's scheme, while `Proxies::proxy_for` looks only at the scheme's own proxy and `all`. The doc says "the proxy for `https`". Same cause as 19-4: the choice is not made by the route, so asking `ProxyChoice::route` for the page fixes both. The test `yt_dlp_and_the_updater_take_the_proxy_for_https` never reaches the `http` fallback, since `all` is set in both of its cases.
- Confidence: certain

### B15-2 [P3] Copy from system turns a SOCKS4 server into a SOCKS5 profile

- Where: `crates/settings/src/proxy.rs`, `parse_server`; against `crates/engine/src/proxy.rs`, `Proxies::adopt`
- Category: wrong implementation
- Failure: the system's proxy is `socks=host:1080` on a server that speaks only SOCKS4. System mode works for IPv4 destinations. Copy from system saves a SOCKS5 profile, `profile_url` writes `socks5h://`, and every request through it fails, with its test reporting the proxy unreachable.
- Evidence: `adopt` writes `socks4://` with the comment "SOCKS4, the only version it speaks". `parse_server` maps `socks4` and `socks4a` to `ProxyKind::Socks5`, and a test pins that mapping. `ProxyKind` has no SOCKS4 (D73.1), and D73.9 does not record what a copy of one becomes. A server speaking both versions is unaffected, and it shows in the background test rather than silently. Same area as 09-2: the system's `socks=` entry is not followed through.
- Confidence: likely
